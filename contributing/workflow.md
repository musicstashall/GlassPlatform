# Рабочий процесс

## Рабочий процесс

**Стиль взаимодействия: сначала план — потом выполнение.**

1. Получив задачу, ассистент сначала излагает **план изменений** — какие файлы будут затронуты и что именно изменится.
2. Приступает к выполнению **только после явного подтверждения** («ок», «давай», «выполняй»).
3. После выполнения — краткий итог: что сделано, что изменилось; коммит в Git с комментарием + доклад хэша в чате - только после подтверждения удовлетворительного результата пользователем (коммит сразу после правки без проверки запрещён).

Исключение: мелкие очевидные правки (опечатки, однострочные фиксы) можно вносить без плана, если это явно следует из контекста.

### Организация работы с файлами

**Все изменения вносятся напрямую в рабочий репозиторий** `D:\VS_PROJECT\DWM\GlassProject\` — никаких воркдеревьев.

**Перед началом реализации** ассистент сохраняет оригиналы изменяемых файлов в резервную папку:
```
D:\VS_PROJECT\DWM\GlassProject\_backups\<YYYY-MM-DD_HHMM>\
```
Структура папки повторяет структуру репозитория, например:
```
_backups\2026-03-14_1530\
  GlassCore\src\Subsystems\Animation.cpp
  WndCompat\Popup\ComboLBox\ComboBoxSubclass.cpp
```

**Сборка** — всегда из основного репозитория:
```bat
"C:\Program Files\Microsoft Visual Studio\2022\Professional\MSBuild\Current\Bin\MSBuild.exe"
  GlassProject.sln /p:Configuration=Debug /p:Platform=x64
```

Выходной каталог для сборки используй указанный в .vcxproj файле проекта. Не используй для сборки выходной каталог в папке проекта.
Такой порядок позволяет пользователю сразу запустить отладчик в VS и проверить результат, а при необходимости откатиться — скопировав оригиналы из `_backups\` обратно.

**Запуск платформы и тесты** — только пользователь; ассистент не вызывает start/stop и не освобождает DLL за пользователя. См. [build.md](build.md).

### Кодировка новых файлов

После **каждого создания** или полной перезаписи текстового файла — сразу проверить, что на диске **UTF-8 без BOM**, а не UTF-16. При `FF FE` или сообщении «binary» — исправить немедленно; безопаснее, пока файл пустой или короткий. Подробно: [file-encoding.md](file-encoding.md).

### Временные скрипты и порядок в репозитории

Не создавать в корне solution и в каталогах исходников (`GlassCore/`, `WndCompat/`, `.cursor/skills/` и т.п.) разовые `.py`, `.ps1`, `.bat` для обхода кодировки или автоматизации. Одноразовые скрипты ассистента — только в **`.claude/tmp/`**; после использования **удалить**. Постоянные утилиты проекта — в **`tools/`** или **`scripts/`**. Подробно: [repo-hygiene.md](repo-hygiene.md).
