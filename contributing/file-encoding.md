# Кодировка текстовых файлов

В репозитории все **текстовые** файлы (`.md`, `.cpp`, `.h`, `.py`, `.xml`, `.rc`, скиллы `.cursor/skills/**/SKILL.md` и т.д.) должны быть **UTF-8 без BOM**.

На Windows инструменты ассистента иногда создают файл в **UTF-16 LE** (BOM `FF FE`). Такой файл в IDE/сборке ведёт себя как «бинарный», ломает diff и чтение через Read.

## Обязательно для ассистента

**Сразу после создания или перезаписи нового файла** — проверить кодировку, **до** дальнейших правок и наполнения содержимым.

Безопаснее исправить UTF-16, пока файл **пустой или почти пустой** (заголовок, пара строк), чем после большого объёма текста.

## Как проверить

Признаки UTF-16:

- Read/редактор сообщает, что файл «binary» или нечитаем;
- первые байты `FF FE` (UTF-16 LE) или `FE FF` (UTF-16 BE);
- в дампе каждый второй байт ASCII-символа — `00`.

Проверка:

```bat
python -c "from pathlib import Path; p=Path(r'путь\к\файлу'); b=p.read_bytes()[:4]; print(b)"
```

Ожидаемо для UTF-8: `b'---'`, `b'// '`, `b'# '` — **без** `b'\xff\xfe'` в начале.

## Как исправить

### Файл пустой или только создан

```bat
python -c "from pathlib import Path; p=Path(r'путь'); p.write_text('', encoding='utf-8', newline='\n')"
```

Затем записать содержимое через `write_text(..., encoding='utf-8')` или `StrReplace`.

### Уже есть содержимое

```bat
python -c "from pathlib import Path; p=Path(r'путь'); t=p.read_text(encoding='utf-16'); p.write_text(t, encoding='utf-8', newline='\n')"
```

Если `utf-16` не читается — остановиться и спросить пользователя.

### Новые файлы в `.cursor/`

Если Write даёт UTF-16: сначала пустой UTF-8 через Python, затем заполнение и повторная проверка байт.

## Чего не делать

- Не оставлять UTF-16 «на потом».
- Не конвертировать вслепую большой файл, если чтение падает с ошибкой.
- Не добавлять UTF-8 BOM без необходимости.
