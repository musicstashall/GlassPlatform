# GlassSetup — Win32 / C++17

Окно мастера установки GlassPlatform: **x86 (Win32)**, MSVC и WebView2. Деинсталлятор `GlassUnins` использует тот же автономный HTML и нативный резервный интерфейс. Сборка выполняется через **`GlassProject.sln`**.

Инструкции: [объединённая инструкция](docs/GlassSetup.md), [WiX и Visual Studio](docs/GlassSetup-WiX-VisualStudio.md), [OpenGlass и реестр](docs/OpenGlass-install-registry.md).

## Сборка полного комплекта в Visual Studio

Нужны Visual Studio 2022 с C++ v143 и Windows SDK, .NET SDK, WiX/HeatWave и восстановленные пакеты NuGet. Для MSI должны быть готовы входные файлы OpenGlass и SecureUxTheme, как в существующей конфигурации проекта.

1. Откройте `GlassProject.sln`; при запросе перезагрузите изменённые проекты и выполните **восстановление пакетов NuGet**. Если решение было открыто во время Pull, надёжнее закрыть и снова открыть его, чтобы обновились зависимости проектов.
2. Выберите **Release | x64** и соберите всё решение. Этот проход создаёт x64-компоненты, `GlassSettings.Native.dll`, деинсталлятор и x64 MSI.
3. Затем выберите **Release | x86** и снова соберите всё решение. Он создаёт x86 MSI и `Build\GlassSetup\Release\GlassSetup.exe` с пятью встроенными MSI и обеими версиями `GlassSettings.Native.dll` для Unlocker.

Используются пять SDK-style WiX-проектов. `global.json` закрепляет `WixToolset.Sdk` **6.0.2**, NuGet-источник задан в `nuget.config`. Для работы с `.wixproj` в обозревателе Visual Studio может понадобиться расширение **HeatWave Community Edition**; для MSBuild из командной строки оно не обязательно. Не запускайте миграцию SDK-style проектов WiX как проектов WiX v3. Если проект отображается как несовместимый после обновления, восстановите NuGet и перезагрузите решение; при необходимости закройте VS и удалите только её локальный кэш `.vs`.

MSI записываются в `Build\GlassSetup\msi\Release\<имя проекта>\<имя проекта>.msi`: `Glass-x64`, `Glass-x86`, `GlassSettings-x64`, `GlassSettings-x86`, `OpenGlass-x64`. RC включает их непосредственно из `Build`; если нужного файла или Native DLL нет, Release-сборка Setup завершается ошибкой, а не использует заглушку. Перед компиляцией ресурсов скрипт проверяет разрядность и наличие строкового маркера протокола в обеих Native DLL, чтобы не включить очевидно старую сборку; полная проверка PE и протокола выполняется установщиком. `GlassUnins.exe` встраивается в MSI как `unins000.exe`.

Порядок важен: Release-сборка использует общую сессию версии комплекта. Отдельная сборка x86 Setup без результатов x64 не содержит необходимые ресурсы. При необходимости отменить незавершённую сессию:

```bat
msbuild GlassProject.sln /t:GlassBundleCancelSession /p:Configuration=Release /p:Platform=x64
```

Сборка sparse-пакета оболочки использует локальный **разработческий сертификат**. Его закрытый ключ не входит в комплект; не копируйте PFX на другие машины. На Windows 11 тестовая VM должна доверять подписи поставляемого MSIX либо допускать регистрацию манифеста в режиме разработчика. Установщик сам не создаёт и не добавляет доверенные сертификаты; при недоверенной подписи регистрация оболочки может завершиться ошибкой и установку придётся откатить. Для распространения нужна отдельно проверенная цепочка подписи. Также проверьте наличие совместимых VC++ Runtime (x64 и x86): встроенный `GlassSettings.Native.dll` может использовать динамическую CRT.

Скрипт Authenticode `Shared/scripts/Invoke-GlassSign.ps1` и target `Shared/GlassSign.targets` существуют, но target запускается только при заданном `GlassSignPaths`. В текущих проектах список не задан: **нельзя считать, что PE и MSI автоматически подписаны**. Перед публикацией необходимо настроить список файлов и проверить подписи. `GlassSign=Skip` явно отключает этот target. Не путайте Authenticode PE/MSI с отдельной подписью sparse MSIX.

Для Debug выбирайте **Debug | x86**: сам `GlassSetup` и его `GlassShared` всегда 32-битные. В конфигурации решения Debug | x64 установщик не участвует в автоматической сборке. Debug-сборка `GlassSetup` без встроенных MSI симулирует установку. Автоматический просмотр страниц включается только ключом `--demo-tour`; этот режим не устанавливает продукты. Чтобы проверить откат, запустите Debug **без** `--demo-tour`, дойдите до имитации установки и подтвердите отмену. Повторите на разных процентах: за время подтверждения ширина запоминается; во время имитации отката (около пяти секунд) левый край полосы остаётся на месте, а правый плавно сдвигается к нулю. Процент соответствует оставшейся ширине. Это проверка интерфейса, а не настоящего MSI-отката. При настоящем откате полоса может временно останавливаться на этапах MSI и восстановления, для которых точный прогресс недоступен; до нуля она доходит только после успешного завершения. `GlassUnins` в решении собирается как Release|Win32.

Для отдельной проверки раннего окна запустите Debug с аргументом `--debug-slow-startup`: фоновая подготовка специально задерживается примерно на четыре секунды. Сначала должен появиться «бублик» по центру содержимого; окно должно перетаскиваться и закрываться через `X` или Escape во время задержки. Если анимации Windows отключены, индикатор неподвижен в соответствии с системной настройкой. Аргумент действует только в Debug; уберите его после проверки. До окна Windows может показать стандартный запрос UAC — он не управляется установщиком.

## Фиксированные каталоги и проверка прежних установок

Путь установки выбирается системой, а не пользователем. На 64-битной Windows x64 использует системную папку `Program Files` + `\GlassPlatform`, x86 — `Program Files (x86)` + `\GlassPlatform`. На 32-битной Windows используется системная папка Program Files + `\GlassPlatform`. Диск и реальные имена системных папок определяются Windows; буква `C:` не зашита. GlassSettings находится в подпапке `GlassSettings` соответствующей платформы, OpenGlass — в подпапке `OpenGlass` x64-платформы.

Setup и GlassUnins не используют произвольные пути из реестра, команд задачи или старого `unins000.exe` как цели установки, очистки или запуска. Перед остановкой хостов Setup проверяет известные регистрации и видимые связанные коды продуктов, cached MSI, контекст установки, зарегистрированные пути компонентов и действия задач/службы; GlassUnins проверяет выбранные продукты и задействованные задачи/службу. Пути MSI за пределами соответствующего фиксированного корня, отсутствующие сведения, неоднозначный контекст, неподдерживаемые таблицы MSI, посторонние команды задачи/службы, ссылки/reparse points в проверяемых путях или несколько жёстких ссылок на проверяемый файл приводят к остановке с диагностикой. Проверки повторяются перед важными MSI-операциями; при обнаружении проблемы в ходе установки запускается откат, насколько это безопасно. Некоторые обычные, но неподдерживаемые старые конфигурации тоже могут быть отклонены.

Проверки и сами операции не являются единой атомарной транзакцией: изменения другими процессами, hard links, неизвестные сторонние продукты и установки других пользователей полностью не исключены. При сомнении не удаляйте файлы, задачи или записи MSI/реестра вручную: сохраните журнал и обратитесь за помощью. Независимый OpenGlass в общем каталоге следует проверять только на VM с контрольной точкой.

## Изменение состава установленного комплекта

На странице выбора показано состояние каждого продукта и действие: установленный отмеченный продукт будет обновлён, снятый установленный — удалён, отсутствующий отмеченный — установлен. Цветные этикетки обозначают установку зелёным, обновление жёлтым и удаление красным; если продукт отсутствует и не выбран, этикетки нет. Основная платформа разрядности Windows обязательна и обозначена замком. На 64-битной Windows отказ от x86 отключает эффекты и возможности платформы в 32-битных приложениях; отказ от GlassSettings означает ручное изменение параметров в реестре. Оба предупреждения отображаются одновременно.

Состояние определяется по известным текущим и прежним MSI-кодам GlassSetup. Независимая установка OpenGlass может не распознаваться, а общий каталог пока не защищён от возможной перезаписи. Сценарии с самостоятельно установленным OpenGlass проверяйте только на VM с контрольной точкой.

Перед изменениями Setup сохраняет доступные старые MSI, файлы и относящиеся к установке значения реестра. Для удаляемых продуктов отдельно проверяются и сохраняются определения задач и их права, ярлык GlassSettings и ветка реестра службы OpenGlass. Если задача требует недоступных учётных данных, задача или ярлык указывают на другую программу, служба указывает на другую программу или использует другую учётную запись, либо невозможно сохранить права, Setup останавливается **до изменения MSI**. Существующая служба OpenGlass не пересоздаётся с потерей настроек: её удаление происходит только после успешной проверки выбранных продуктов и обратимых операций, на заключительной стадии, где отмена уже недоступна. На более ранних стадиях кнопка, Escape и `X` по-прежнему запускают кооперативную отмену и откат.

MSI удаляет принадлежащие ему файлы. После удаления снятого продукта мастер дополнительно пытается удалить пустые каталоги, включая каталог OpenGlass. Дополнительная очистка не удаляет файлы пользователя, непустые каталоги, ссылки/reparse points и каталоги оставленных продуктов; при сомнительных путях она пропускается. При ошибке восстановления дальнейший запуск компонентов может быть пропущен, резервная копия сохраняется, а её путь показывается в деталях; журнал и копию следует сохранить. Откат не может вернуть несохранённые документы закрытых приложений, историю выполнения задач, изменения других процессов или гарантировать восстановление после аварийного выключения.

Состояние OpenGlass фиксируется вскоре после появления первого окна мастера. Если его файлов тогда не было, выбранный OpenGlass запускается после установки. Если файлы уже были, он запускается только когда работал при открытии мастера; отдельный более поздний снимок служит для отката. Состояние определяется по фактическому статусу службы и запущенным экземплярам подходящей задачи, включая отключённые, но работающие объекты; само наличие файлов, включённой задачи или окна системного DWM **не означает**, что OpenGlass запущен. Если служба и задачи остановлены, Setup не посылает остановку и не ждёт её. Если состояние нельзя надёжно определить, установка останавливается до изменения пакетов. Если ранее не работающий хост появился после снимка, Setup не останавливает его и просит начать заново.

Если команда остановки уже отправлена, при отмене мастер сначала даёт ей завершиться, чтобы запоздалая остановка не выключила восстановленный хост. После этого он возвращает только состояние, которое действительно изменил. Работающую отключённую службу мастер пытается запустить с восстановлением её прежнего типа запуска; отключённую старую задачу автоматически включать нельзя. Если несколько подходящих задач или экземпляров не позволяют однозначно восстановить ранее работавший хост, Setup отказывает до остановки. Сторонние и неоднозначные конфигурации нужно проверять отдельно; `GetInstances` показывает только экземпляры, доступные контексту безопасности вызывающего.

До резервной копии и остановки хостов Setup проверяет разрядность и версионированный экспорт встроенных Native DLL, читая PE-файл без загрузки и выполнения DLL. Если файл отсутствует или не поддерживает нужный протокол, установка прекращается до изменения продуктов. Это предварительная проверка сборки, а не сам мониторинг процессов.

После распаковки, резервной копии и остановки платформы с ожиданием исчезновения её мьютексов мастер сначала устанавливает выбранный GlassSettings. Состояние x86/x64 платформы определяется её мьютексом, а не фактом существования/включения задачи. Команду остановки нельзя заменять ранним `schtasks /End`: принудительное завершение хоста до освобождения мьютекса может повредить работу Explorer. Пустой результат первоначального обнаружения не отменяет последующего мониторинга, в том числе на чистой установке. Если GlassSettings снят, его MSI на этом этапе не запускается. Затем из защищённого временного каталога загружаются встроенные DLL комплекта: x86 — в Setup, x64 — в `rundll32` на 64-битной Windows. Они используют существующий сканер и Unlocker `GlassSettings.Native`, без отдельного сканера в Setup; по завершении операции временные библиотеки освобождаются и удаляются. Если файл не удаётся удалить сразу, попытка удаления после перезагрузки и ошибка фиксируются в журнале. Ошибка или неполный результат проверки блокируют продолжение, в том числе при чистой установке. Если остаются модули, мастер спрашивает разрешение на выгрузку, повторно сканирует и при необходимости показывает страницу закрытия процессов; остальные MSI запускаются только после освобождения модулей. Отмена или ошибка на странице мониторинга откатывает раннюю установку GlassSettings, не перезаписывая ещё занятые файлы платформы. Explorer и сам мастер не завершаются и не выгружаются принудительно; для Explorer отправляется штатный запрос освобождения, а после подтверждения могут закрываться только окна файлового менеджера. Если модули всё ещё заняты, установка ожидает дальнейших действий пользователя или отмены.

`GlassSetup` — Win32, поэтому для x64 используется `Sysnative\rundll32.exe`, а не `System32` с WOW64-перенаправлением. Временная x86-копия имеет отличительное имя `GlassSetup.Native.x86.dll`; после загрузки Setup сверяет фактический путь и ответ протокола. Журнал позволяет отличить несовместимый встроенный файл, неверный загруженный путь и ошибку ответа DLL. Перед запуском также проверяется экспорт `GlassSettings_UnlockerW`; колбэк Rundll32 может передать аргументы как ANSI, поэтому парсер поддерживает и ANSI, и UTF-16. `GlassSettings.exe` не игнорируется: мастер отдельно добавляет его в список занятых процессов и предлагает штатное закрытие без принудительной выгрузки. При неполной проверке установку продолжать нельзя.

## Текущие ограничения

- WebView2 Runtime не входит в комплект. Если он отсутствует, Setup предлагает онлайн-загрузку или закрытие; нативные страницы служат резервом при сбое представления.
- Пункты «Установленных приложений» используют `unins000.exe`; после установки Setup записывает `NoModify=1` и `NoRepair=1` в ARP. Реальную работу каждого пункта нужно проверить в Windows.
- Автоматическая Authenticode-подпись PE/MSI не настроена; отдельная подпись sparse MSIX также требует проверки доверия.
- Независимый Inno-установщик OpenGlass не распознаётся как MSI GlassSetup. Общий каталог может быть перезаписан, и безопасное обновление такой установки не гарантируется.

## Проверка перед публикацией

Сначала проведите проверку **в тестовой Windows VM с контрольной точкой**. Автотест исходников не выполняет настоящих MSI-операций и не доказывает работоспособность отката:

```bat
python GlassSetup\tests\verify_resources.py
```

Дополнительно `GlassSetup\tests\selection_tests.cpp` проверяет правила выбора продуктов, `removal_order_tests.cpp` — порядок операций, `progress_tests.cpp` — полосу установки и отката, `unlock_state_tests.cpp` — возврат к слайдам, `empty_directories_tests.cpp` — безопасный обход пустых каталогов. Это независимые C++17-тесты без Windows SDK. Python-сценарии `*_mock.py` в той же папке компилируют с GCC/Clang фрагменты реального кода с имитацией Win32/COM и проверяют сканер, протокол, отмену и OpenGlass; для них нужны Python 3 и g++ (или `CXX` с другим совместимым компилятором). Эти имитации не проверяют реальные задачи, службы или MSI.

Проверку путей выполняйте **только в изолированной VM** с контрольной точкой и копией контрольных файлов. В логе нового Release-запуска найдите строку `Target x64=… x86=… OpenGlass=…`: она должна содержать только системные фиксированные каталоги. Для тестовой старой MSI-регистрации с файлами в папке разработки и для чужой команды задачи/службы ожидается остановка до MSI с диагностикой; убедитесь, что контрольные файлы и задача не изменились. Отдельно проверьте обычную установку в фиксированный каталог, родительский junction/reparse point, ранее установленный продукт и выборочное удаление. Не создавайте и не исправляйте такие регистрации на рабочей машине.

Если конфликт обнаружен уже после начала последовательности MSI в GlassUnins, часть продуктов может быть удалена; деинсталлятор не обещает полного отката после начала удаления. Сохраняйте журнал и используйте контрольную точку VM.

Проверьте раннее окно и закрытие при загрузке, отсутствие WebView2, повторный запуск и резервный нативный интерфейс; также проверьте DPI на нескольких мониторах. Затем проверьте на x64 и, если поддерживается, x86 Windows: чистую установку с разными комбинациями; обязательную платформу системной разрядности; предупреждения при отказе от x86 и GlassSettings, в том числе оба сразу; видимость продуктов в «Установленных приложениях»; выборочное удаление и зависимые продукты; старт и сохранение отключённых задач.

На VM сначала установите все продукты. Убедитесь, что при старте настоящей Release-установки отдельное окно Windows Installer «Подготовка к установке» не появляется; проверка только в Debug-имитации для этого недостаточна. При повторном запуске снимите OpenGlass, завершите установку и проверьте отсутствие его MSI, службы `OpenGlassHost` и задач `OpenGlass Host` / `OpenGlass Legacy Host`. Верните контрольную точку и отдельно повторите для x86 (проверьте задачу `GlassPlatform.Win32 Autorun Task (x86)`) и GlassSettings (оба возможных MSI и ярлык); проверьте также одновременное снятие всех трёх. Нативная платформа и оставленные пользовательские файлы должны сохраниться. Повторите для прежних MSI и режима чистой переустановки.

На VM отдельно проверьте освобождение занятых модулей кнопкой «Повторить» и, если нужно, разблокировку процессов: пока операция выполняется показывается её экран, после успешного освобождения и продолжения установки снова показываются слайды. Проверьте также чистую установку с оставшимися модулями, отказ x64-помощника, занятый GlassSettings и отмену во время сканирования: MSI не должен начаться при неполном результате. Проводник и мастер не должны принудительно завершаться. Если модули всё ещё заняты, должно появиться следующее подтверждение, а не слайды.

Отдельно проверьте OpenGlass: первую установку без файлов; переустановку, когда он был запущен при открытии мастера; переустановку, когда был остановлен; изменение состояния после открытия мастера; отключённую службу и старую задачу. При остановленной службе и остановленных задачах, даже если обычное окно DWM существует, не должно быть ни команды остановки, ни ожидания её тайм-аута; уже остановленный OpenGlass не должен запуститься при отмене. Для работающей службы и работающей задачи проверьте штатную остановку, отмену во время неё и восстановление именно прежнего состояния. Повторите при открытом подтверждении отмены, если операция успела завершиться ошибкой: подтверждённая отмена должна приводить на страницу отмены, а не на страницу прежнего тайм-аута; настоящий сбой восстановления должен оставаться заметным. Для очистки проверьте пустые и непустые каталоги, пользовательские файлы, нестандартные и вложенные пути, ссылки и отмену после удаления. Сравните с контрольной точкой, включая пустые каталоги оставленных продуктов.

На обновлении и чистой установке проверьте отмену через кнопку, Escape и `X` во время распаковки, снимка, Unlocker, удаления и установки MSI. Дождитесь окончания отката и сравните файлы, записи MSI, реестр, XML/права/состояние задач и конфигурацию службы с контрольной точкой; отдельно проверьте задачи с сохранённым паролем, чужим действием и недоступными правами — до изменения пакетов должна появиться понятная ошибка. Убедитесь, что страница запуска показана не менее пяти секунд.

Закрытие сторонних процессов в Unlocker может привести к потере их несохранённых данных; откат не запускает эти приложения и не возвращает их документы. Регистрацию старых/осиротевших shell-компонентов и восстановление прав файлов также проверяйте отдельно; непроверенный программный откат не заменяет контрольную точку VM.

При сбое отката сохранённая резервная копия остаётся в защищённом каталоге `Windows\Temp\GlassRollback-*`; её путь указывается в логе/деталях ошибки. **Не удаляйте резервную копию до выяснения причины.** Системный откат после аварийного выключения, принудительного завершения процесса или перезагрузки требует отдельной проверки; для восстановления тестовой машины используйте контрольную точку VM.

## Журналы и отладка

- `%WINDIR%\Temp\GlassSetupLogs-*`: `GlassSetup.log` и подробные MSI-журналы установки.
- `%WINDIR%\Temp\GlassUninsLogs-*`: `GlassUnins.log` и `GlassInstallSupport.log` деинсталляции. При перезапуске деинсталлятора могут создаться два каталога — посмотрите последние по времени.
- Эти каталоги доступны администраторам и SYSTEM. Если они не созданы, запись журналов отключена: небезопасный `%TEMP%` как запасной путь не используется.
- Если MSI завершился успешно, а проверка модулей всё равно завершилась ошибкой, это разные этапы. Для диагностики нужны строки `Watch:`, включая запрошенный/загруженный путь, экспорты и ответ протокола; одно сообщение об ошибке протокола само по себе не доказывает, какая DLL была загружена и почему.
- При ошибке сборки приложите полный текст **Вывод → Сборка** в Visual Studio, конфигурацию, разрядность, версию Windows и шаг воспроизведения. При ошибке выполнения также приложите журналы и скриншот. Если падает Explorer, сохраните событие «Ошибка приложения» и/или Windows Error Reporting из **Просмотр событий → Журналы Windows → Приложение** за то же время: нужны имя сбойного приложения и модуля, код исключения и время. Перед отправкой удалите персональные данные и секреты.

WebView2 Loader (x86) статически находится в `third_party/`. Мастер предлагает загрузить Microsoft Edge WebView2 Runtime при его отсутствии; деинсталлятор может показать страницы в нативном резервном режиме.
