# Оставшиеся нереализованные шаги

На согласование. Закрытые этапы лёгкого Setup, официальный silent-запуск OpenGlass, пакет Resources, controller, резервная копия и очистка в этот список не входят. Приёмка на Windows остаётся в [controller-windows-acceptance.md](controller-windows-acceptance.md) и новым шагом реализации не является.

Исторические планы удалены: разбор извлечения DLL из `OpenGlassSetup.Signed.exe`, журнал обслуживания Settings, аудит от 2026-11-04 и черновик единого процесса удаления. Их формулировки «ещё не сделано» больше не backlog.

## N2. Обновления установленных продуктов Glass в GlassSettings

`GlassReleaseUpdateService.TryFetchLatestAsync` читает одно поле `glass` из `version.json` и сравнивает его с версией платформы.

Нужен провайдер по продукту:

- отдельные версии и архитектуры установленных продуктов;
- одна сводная строка, если обновлений несколько, а не длинный список;
- закрытое уведомление запоминается для продукта, архитектуры и версии; новая версия уведомляет снова;
- отсутствие сети не показывается как отсутствие обновлений.

Кнопки «Обновить» по-прежнему только запускают закэшированный Setup. Settings не скачивает MSI и не ставит продукты.

## N3. Обновления OpenGlass в GlassSettings

`OpenGlassReleaseUpdateService.TryFetchLatestLegacyReleaseAsync` выбирает только теги, в которых есть `-legacy`.

Нужно:

- учитывать актуальные релизы без суффикса;
- сопоставлять релиз установленному варианту DWM и каналу;
- не переключать канал только потому, что появился другой тег;
- предлагать ремонт после смены сборки Windows.

## Что в список не входит

Выключение OpenGlass тумблером и пункт Delete уже сходятся в `OpenGlassInstallService.Uninstall`: служба удаляется, старая задача снимается. Отдельного шага реализации здесь нет.

Удаление SecureUxTheme при уже загруженном hook по-прежнему запрещено `SecureUxUnloadedRemoval`. Это существующая граница, не шаг этого списка.

Падение Explorer, переход подписи на SignPath и документы вне GlassSetup сюда не входят.
