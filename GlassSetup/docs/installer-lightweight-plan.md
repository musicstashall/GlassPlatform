# Оставшиеся нереализованные шаги

Список пуст. Приёмка на Windows остаётся в [controller-windows-acceptance.md](controller-windows-acceptance.md) и шагом реализации не является.

## N2. Обновления установленных продуктов Glass

Сделано в `GlassReleaseUpdateService` и `ProductUpdateCoordinator`. Каталог `version.json` читается по `products[]`: платформа сравнивается по ProductVersion, Settings — по `payloadVersion`, Resources — по DisplayVersion установленного MSI. Поле `glass` остаётся запасным сравнением только для платформы. Несколько обновлений показываются одной строкой со счётчиком. Закрытие запоминается как продукт, архитектура и версия. Неудачная проверка не записывает время успеха и не стирает уже найденное обновление; вместо «обновлений нет» показывается отдельная строка. Кнопка по-прежнему только запускает закэшированный Setup.

## N3. Обновления OpenGlass

Сделано в `OpenGlassReleaseUpdateService`. Берутся стабильные теги без суффикса и теги `-legacy`. Канал выбирается по FileDescription установленной DLL: `(MILComp)` или `(Legacy)`. Более новый тег другого канала сам по себе канал не меняет. Если сборка Windows больше не совпадает с вариантом DLL (порог 28000, как в установщике), предлагается ремонт канала, который подходит текущей сборке. Кнопка тоже только запускает закэшированный Setup.

## Что в список не входит

Выключение OpenGlass тумблером и пункт Delete уже сходятся в `OpenGlassInstallService.Uninstall`. Удаление SecureUxTheme при загруженном hook по-прежнему запрещено `SecureUxUnloadedRemoval`. Падение Explorer, переход подписи на SignPath и документы вне GlassSetup сюда не входят.
