# GlassSetup и WiX в Visual Studio 2022

> **Безопасность тестирования:** Setup и GlassUnins запускаются с правами администратора, но не проверяют подлинность исполняемых файлов комплекта GlassPlatform по подписи или доверенным эталонам хэшей и не удостоверяют защищённость каталогов с помощью проверки их прав. Поэтому используйте только доверенные файлы и проверенные зарегистрированные пути; реальные установку и удаление проверяйте в изолированной Windows VM с контрольной точкой, не на рабочей установке.

Инструкция описывает сборку исходников `GlassSetup` в Visual Studio 2022. Реальную сборку MSVC/WiX и установку проверяйте на Windows; для первых испытаний используйте тестовую VM с контрольной точкой.

## Что установить и открыть

- Visual Studio 2022: рабочая нагрузка C++ для классических приложений, компилятор v143 и Windows SDK; также нужен совместимый .NET SDK для GlassSettings.
- Восстановленные NuGet-пакеты. В корневом `nuget.config` указан `https://api.nuget.org/v3/index.json`. Версия `WixToolset.Sdk` **6.0.2** закреплена в корневом `global.json`.
- Для удобной работы с SDK-style `.wixproj` в Visual Studio может понадобиться **HeatWave Community Edition**: `Extensions → Manage Extensions → Online` → найти HeatWave → установить, закрыть все окна VS и открыть решение снова. Вызов MSBuild из Developer Command Prompt сам по себе не требует этого расширения, но нуждается в доступном или восстановленном SDK.
- Входные Release-файлы OpenGlass и SecureUxTheme должны присутствовать в местах, ожидаемых `GlassSetup/msi/GlassSetupPayload.targets`.

Откройте `GlassProject.sln`. После получения изменений перезагрузите изменённые проекты, затем выполните восстановление NuGet-пакетов. Если WiX-проекты помечены как несовместимые, проверьте SDK и HeatWave и перезапустите VS. При необходимости после закрытия VS удалите **только локальный кэш `.vs`** и откройте решение заново. Не применяйте мастер миграции проектов WiX v3 к этим SDK-style проектам.

Проекты используют `<Project Sdk="WixToolset.Sdk">` и версию из `global.json`. Не добавляйте `PackageReference` для самого `WixToolset.Sdk` и не меняйте его версию без отдельного обновления комплекта.

## Получение изменений в Visual Studio

1. Сохраните свои файлы. В окне **Изменения Git** проверьте, нет ли незакоммиченных изменений; если они есть, сначала сохраните их или уточните порядок действий. Не используйте Reset для обновления.
2. В Visual Studio проверьте текущую ветку: должна быть `arena/5f91bc09-glassplatform`. Если она другая, откройте **Git → Управление ветвями** и выберите эту ветку; при необходимости выберите её в `origin` и выполните Checkout с отслеживанием. Не изменяйте `master`.
3. Выполните **Git → Получить (Pull)**. Одна команда **Извлечь (Fetch)** только получает сведения с сервера и не обновляет файлы выбранной ветки. Если появится конфликт или ошибка, остановитесь и сохраните сообщение.
4. Закройте и снова откройте `GlassProject.sln`, восстановите NuGet и при запросе перезагрузите проекты. Затем выполните оба Release-прохода ниже.

## Полная Release-сборка

В панели конфигурации Visual Studio и меню **Сборка → Собрать решение** выполните строго два прохода:

| Проход решения | Основные результаты |
|---|---|
| **Release \| x64** | x64-модули и Native, GlassSettings x64, GlassUnins, `Glass-x64`, `GlassSettings-x64`, `OpenGlass-x64` MSI. Сам Setup не собирается. |
| **Release \| x86** | x86-модули и Native, GlassSettings x86, `Glass-x86`, `GlassSettings-x86` MSI и Win32 `GlassSetup.exe`. Ранее собранные x64 MSI используются из `Build`. |

Полный установщик: `Build\GlassSetup\Release\GlassSetup.exe`. Он встраивает **пять MSI** и обе версии `GlassSettings.Native.dll`. `GlassUnins` собирается как Release Win32 и помещается внутрь MSI под именем `unins000.exe` с файлом `unins000.dat` для нужного продукта.

Каждый MSI находится в `Build\GlassSetup\msi\Release\<имя проекта>\<имя проекта>.msi`:

- `Glass-x64\Glass-x64.msi` и `Glass-x86\Glass-x86.msi`;
- `GlassSettings-x64\GlassSettings-x64.msi` и `GlassSettings-x86\GlassSettings-x86.msi`;
- `OpenGlass-x64\OpenGlass-x64.msi`.

`GlassSetup/res/GlassSetup.rc` обращается к артефактам в `Build` напрямую. Проект Setup проверяет их наличие перед компиляцией ресурсов: при отсутствии нужного MSI или Native DLL сборка Release должна выдать ошибку, а не молча использовать заглушку. Сам Setup не запускает вложенную сборку x64 WiX из x86-проекта.

Проект Setup имеет ссылку сборки на x86 `GlassSettings.Native` без линковки его import-библиотеки. Перед компиляцией ресурсов `Verify-InstallerNative.ps1` проверяет разрядность и наличие маркеров протокола мониторинга и пути оболочки в обеих DLL. Встроенные DLL всё равно могут оказаться устаревшими, если использовать старый `GlassSetup.exe` или результаты предыдущей сборки; после обновления исходников перезагрузите решение и выполните оба прохода. Перед изменением продуктов Setup проверяет поддержку обоих протоколов встроенных DLL по PE-экспортам. При несовместимости он сообщает об этом до остановки хостов и предлагает пересобрать комплект; сам мониторинг и runtime-handshake выполняются позже. Сравнивайте журнал именно нового запуска.

Проекты `GlassSettings-x64/x86` включены в matrix решения. Для WiX Debug сборка MSI выключена. `GlassSettings` публикует файлы для MSI в `Build\<архитектура>\Release\GlassSettings\`; при сборке отдельного WiX-проекта внутри VS заранее убедитесь, что соответствующая публикация уже готова. Staging/harvest выполняет `GlassSetupPayload.targets` в `Build\SetupPayload\...`.

Сборка использует общую сессию версии комплекта. Не удаляйте её и не меняйте версию между двумя проходами без необходимости. При необходимости отменить незавершённую сессию в Developer Command Prompt из корня репозитория:

```bat
msbuild GlassProject.sln /t:GlassBundleCancelSession /p:Configuration=Release /p:Platform=x64
```

`Release | Any CPU` не является проходом полного установочного комплекта. Не меняйте вручную архитектурные привязки WiX-проектов ради обхода указанного порядка.

## Debug

Выберите **Debug | x86**: Setup и его `GlassShared` — Win32. В `Debug | x64` Setup не участвует в автоматической сборке решения. Debug без `GLASS_EMBED_MSI` показывает имитацию, но не выполняет MSI-операции и не заменяет тестирование Release.

```bat
msbuild GlassProject.sln /t:GlassSetup /p:Configuration=Debug /p:Platform=x86
```

Артефакт: `Build\GlassSetup\Debug\GlassSetup.exe`; промежуточные файлы — `Cache\GlassSetup\Win32\Debug\`. `--demo-tour` показывает демонстрационные страницы; `--debug-slow-startup` задерживает подготовку и помогает проверить ранний индикатор. Уберите аргументы для обычной проверки.

## Подпись

`Shared/GlassSign.targets` и `Shared/scripts/Invoke-GlassSign.ps1` существуют; для Release значение `GlassSign` по умолчанию равно `Local`, subject по умолчанию — `CN=Stanislav K.`. Но target запускается только при непустом `GlassSignPaths`, а в текущих проектах этот список не задан. Поэтому **нельзя предполагать, что все PE, MSI и Setup подписываются автоматически**. Для публикации нужно отдельно настроить и проверить подпись всех нужных артефактов; `/p:GlassSign=Skip` отключает этот target.

Подпись sparse MSIX — отдельный процесс. Тестовый сертификат не является доверенной подписью для распространения. Не передавайте закрытый ключ/PFX и не добавляйте его в репозиторий. Подпись и доверие Windows нужно проверить в тестовой VM.

## Пути установки

Без зарегистрированного пути Setup и GlassUnins выбирают системные `Program Files\GlassPlatform` для x64 и `Program Files (x86)\GlassPlatform` для x86 на x64 Windows; на x86 Windows — системный Program Files. Если соответствующий `InstallPathX64` или `InstallPathX86` зарегистрирован, используется он, включая нестандартный каталог. OpenGlass использует собственный зарегистрированный путь или по умолчанию `OpenGlass` внутри корня x64. Команды задач и старый деинсталлятор не задают целевой каталог; интерфейс выбора папки не предусмотрен. Приоритет записей, проверка MSI и важные ограничения безопасности описаны в `GlassSetup.md`. Проверки пути и MSI не подтверждают подлинность исполняемых файлов; настоящие операции проверяйте в изолированной VM с контрольной точкой.

## Дальнейшая проверка и диагностика

1. Проверьте наличие VC++ Runtime обеих разрядностей и доверие к sparse MSIX.
2. Сделайте контрольную точку Windows VM и выполните реальные сценарии установки, выборочного удаления, отмены и отката из `GlassSetup.md`; исходные тесты не выполняют Windows Installer.
3. При ошибке сборки в VS откройте **Вид → Вывод**, выберите **Сборка** и сохраните первую ошибку и последующий вывод вместе с выбранной конфигурацией. Не делайте `Reset` ветки для диагностики.
4. Для отмены конкретного опубликованного коммита откройте **Git → Управление ветвями / Репозиторий Git**, найдите коммит в истории и выберите **Revert (Обратить)**: создаётся новый обратный коммит, без удаления истории. Если нужно отменить серию изменений или есть свои правки, сначала уточните диапазон и сохраните работу; не используйте Reset.

См. также `GlassSetup.md` и `OpenGlass-install-registry.md` в этом комплекте документов.
