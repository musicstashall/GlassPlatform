# Контракт состояний — редакция 2, после ответа пользователя

Дата: 2026-11-04. Этот раздел заменяет противоречащие ему предложения редакции 1 ниже. Изменены только макеты/документация; production engine пока сохраняет старую политику. Падения Explorer вне области работ.

## Дополнительное согласование

Подробный актуальный алгоритм и проверка присланного экспорта: `cache-profile-maintenance-contract.md`.

- Staging/rollback временно разрешены; постоянная история комплектов запрещена.
- Source оставленной старой версии сохраняется только при реальной необходимости обслуживания отличающейся версии; после update/remove автоматически удаляется, когда больше нет installed/transaction/reboot/recovery references. Полный прежний bundle для одного старого MSI не хранить.
- Preflight всех профилей до очистки принят; обнаруженный отказ — не начинать, поздний отказ — частичный результат.
- Не завершать чужие сеансы; при невозможности безопасного изменения предложить выйти и повторить.
- Сброс custom visual style у всех затронутых пользователей при удалении SUT — обязательная отдельная операция, не зависит от checkbox общей очистки. Offline registry reset после logoff — исследуемый путь, не проверенный готовый рецепт.
- Трактовка запрета тихого удаления GlassSettings при установленном SUT подтверждена пользователем; явный UI-план допускает раздельное удаление.
- Экспорт HKLM/DWM: 228 значений, 223 session activity IDs, ни одного совпадения с текущим whitelist OpenGlass. Удаление всего DWM не допускается; точное происхождение всех значений не проверено чистым Windows baseline.

## Принятые правила

| Продукт / действие | Послеоперационное состояние и UI |
|---|---|
| Platform x64 отсутствует или удаляется | Независимый выбор; ⚠ о недоступности оформления 64-битных приложений, карточка жёлтая |
| Platform x86 на Windows x64 отсутствует или удаляется | Независимый выбор; ⚠ о недоступности оформления 32-битных приложений, карточка жёлтая |
| GlassSettings отсутствует или удаляется | Выбор разрешён; ⚠ о ручном редактировании реестра и управлении службами/задачами, карточка жёлтая |
| SecureUxTheme устанавливается/остаётся активным без GlassSettings | Разрешено на ответственность пользователя, ⚠ на карточке SecureUxTheme: ручной контроль стилей и перезапуска системы. Не добавлять Settings автоматически |
| GlassSettings удаляется, SUT сохраняется | SUT не выбирать и не блокировать автоматически; предупреждение и явный UI-план |
| SUT выбран для удаления | Штатный стиль через helper, затем MSI; неудача safe-style preflight по-прежнему останавливает небезопасное удаление. Наличие отдельного helper в постоянной оболочке необходимо даже без Settings |
| OpenGlass | Независимые установка/удаление, без каскада от Platform/Settings |
| Первоначальный выбор на x64 | Platform x64 + Platform x86 + GlassSettings + OpenGlass; SecureUxTheme не выбран |
| «Выбрать всё» | Доступные продукты; не очистка настроек/сертификат. Кнопка выровнена по правому краю панели плана |
| Счётчик | «Выбрано продуктов: N из M» над списком, тот же счётчик в footer; подсказка о скрытых ниже/выше продуктах |
| Установщик: снятая отметка установленного продукта | Keep, а не удаление. Предупреждение об отсутствии только если продукт действительно будет отсутствовать |
| Выделение | Каждая карточка с предупреждением жёлтая, ⚠ под её иконкой; прежнее полупрозрачное окно без нижних кнопок |
| Настройки | Один checkbox для всех локальных пользовательских профилей и относящихся к продуктам общих HKLM/DWM значений. По умолчанию выключен; сбрасывает и настройки сохраняемых продуктов |
| Cache | Только последний успешно установленный комплект; бессрочное хранение истории версий отклонено |

Headless remove Settings при установленном SUT: пользователь подтвердил запрет тихого удаления и право на раздельное удаление через явный UI-план. Поэтому трактуем как **ограничение entry point**, не жёсткую зависимость SUT → Settings: ARP remove не открывает GUI, возвращает отказ с направлением в «Изменить», а UI разрешает сохранить SUT после предупреждения. Если подразумевалось разрешить и тихое удаление с сохранением SUT, это нужно уточнить отдельно. Защитное переключение стиля перед удалением самого SUT не отменено предупреждением.

## Cache: требование и открытая граница транзакции

Предлагаем steady-state layout `%ProgramData%\Packages\GlassPlatform\Current\` с проверенной оболочкой, manifest и полными MSI только актуального комплекта. Путь ARP стабилен. Разные компоненты/архитектуры в Current не являются историей версий. Отказ от обновления одного продукта не должен лишать его доступного repair source: текущий комплект должен содержать источники фактически оставленных версий либо явно поддерживать их восстановление.

Для безопасного обновления может понадобиться временный Staging новой версии и rollback-данные прежней. Это не постоянная история: после успеха/закрытия rollback-window они удаляются; при ошибке сохраняются до recovery с явным статусом. **Открыто:** согласовать временное удвоение части данных на время транзакции и сохранение точных старых MSI для оставленных не обновлёнными продуктов. Если запрещён даже временный staging, нельзя обещать прежнюю надёжность rollback/переживание потери питания.

## Очистка всех профилей: реализуемость и границы

Да, HKCU каждого профиля можно обслужить административным worker, но HKCU самого elevated процесса не представляет всех пользователей.

1. Перечислить реальные профили по ProfileList и SID, валидировать пути/владельцев. Не обходить произвольные каталоги Users. Профили без NTUSER.DAT отметить как неинициализированные, не создавать hive.
2. Загруженный профиль: работать с `HKEY_USERS\<SID>`, не закрывать/не выгружать системный mount. Незагруженный: открыть NTUSER.DAT через приватный offline app hive либо безопасно загрузить под служебным уникальным именем с нужными привилегиями; закрывать/выгружать только собственную загрузку. API и доступность проверить на целевых Windows.
3. Не трогать .DEFAULT, Default User, SYSTEM/LocalService/NetworkService, специальные системные профили или чужие файлы. Наличие SID в SAM без созданного профиля не означает hive для очистки.
4. Обработать оба применимых registry view; HKLM обработать один раз, не на каждого пользователя.
5. В DWM удалять **только whitelist параметров OpenGlass** из SettingsCatalog/RegistrySanity, а не раздел DWM целиком, не базовые Colorization/EnableTransparency Windows. Не удалять регистрацию MSI/пути установки/задачи при операции очистки настроек. Список настроек GlassPlatform и дополнительных OpenGlass веток сверить с фактическими writers до реализации.
6. Активные Settings/процессы других сеансов могут записать параметры обратно. Нельзя гарантировать «все очищено» без координации сеансов. Не завершать чужие сеансы автоматически.
7. Недоступный/занятый/повреждённый hive — явный частичный результат по SID, не успех и не молчаливый пропуск. Предлагается сначала проверить доступность всех профилей, а при ошибке не начинать очистку; гонка между preflight и commit всё равно требует журнала и отчёта.
8. Очистка необратима без отдельной backup-политики. Продукты могли быть успешно удалены, а очистка части профилей — не выполнена; результат обязан разделять эти стадии. По умолчанию не чистить настройки после неуспешного выбранного удаления.

Проверен текущий `GlassShared/src/RegistrySanity.cpp::RemoveUserSettings`: уже удаляет whitelist OpenGlass в **HKCU и HKLM DWM**, но GlassPlatform только текущего пользователя; возвращает void и часть ошибок пропускает. Для новой семантики нужен отдельный план/результат очистки, не простой цикл вокруг текущей функции.

В макетах новая область очистки показана в checkbox/плане, реестр не изменяется. Требуют согласования: поведение при недоступном профиле, координация активных сеансов и временный cache staging. Техническая проработка конкретного системного SUT MSI/direct uninstall также остаётся открыта.

# Контракт состояний и операций продуктов — на согласование

Дата: 2026-11-04. Редакция 1. Production-код не изменён.

Область: GlassSetup, GlassUnins, управление из GlassSettings, ARP («Установленные программы»), системный MSI SecureUxTheme и постоянная оболочка. Диагностика/падения Explorer **не входят** в этот этап.

Метки: **Согласовано** — явное решение пользователя; **Предложение** — требует утверждения. Поддержка и безопасность конкретного стороннего MSI должны быть проверены отдельно, таблица не объявляет их реализованными.

## 1. Продукты и зависимости

| ID | Продукт | Доступность | Отношение к другим продуктам | Статус |
|---|---|---|---|---|
| platform-x64 | Glass Platform x64 | Windows x64 | Не требует OpenGlass, Settings или Platform x86. Удаление не выбирает их автоматически | Независимость от OpenGlass/x86/Settings согласована |
| platform-x86 | Glass Platform x86 | Windows x86/x64 | На x64 отдельная установка/удаление; отсутствие поддержки x86 сопровождается предупреждением | Согласовано |
| settings | GlassSettings | Подходящая для ОС архитектура | Допускается без Glass Platform, для управления OpenGlass/SecureUxTheme | Согласовано |
| openglass | OpenGlass | Сейчас комплект поставляется только для Windows x64; поддержку других архитектур эта работа не добавляет | Установка/удаление не требует Glass Platform или GlassSettings | Независимость согласована; ограничения совместимости определяются payload |
| secureuxtheme | SecureUxTheme | MSI подходящей ОС архитектуры; x86 proxy на x64 учитывается как часть комплекта | Системные файлы/регистрацию обслуживает MSI; пользовательский стиль — helper | Разделение обязанностей согласовано |
| controller | Оболочка обслуживания | По архитектуре и составу комплекта | Сохраняется, пока есть управляемые продукты/незавершённая операция | Предложение: отдельный владелец cache/ARP, не обычная карточка продукта |

**D1 — требуется решение:** считать ли GlassSettings обязательной управляющей зависимостью SecureUxTheme? Предлагается **да**: SecureUxTheme не зависит от Platform, но без Settings не должен оставаться без пользовательского управления. Это не техническая зависимость загрузки DLL. Возможная альтернатива — управление целиком постоянной оболочкой, тогда Settings можно удалить независимо.

Далее таблицы исходят из варианта D1=«да»; это **не означает его утверждение**. В макете сохранена текущая связь Settings → выбор SecureUxTheme при удалении.

## 2. Не один статус, а несколько независимых осей

| Ось | Допустимые значения | Для чего используется |
|---|---|---|
| Поддержка | Supported / Unsupported / Unknown | Запрет неподдерживаемых операций, не скрывать причину |
| Владение | Managed / External / Unknown | Не менять чужую установку автоматически |
| Регистрация | Absent / Installed / Broken / Unknown | MSI product/context identity и возможность операций |
| Версия | Older / Same / Newer / Unknown | Install/update/repair и запрет скрытого downgrade |
| Целостность | Healthy / Damaged / Unverifiable | Не подменять непроверяемое состояние успешной проверкой |
| Источник | VerifiedAvailable / Missing / Invalid | Наличие полного, доверенного MSI для установки/восстановления |
| Работа | Running / Stopped / Unknown | Снимок запуска и восстановление процессов |
| Переход | Idle / Installing / Updating / Repairing / Removing / RebootPending / RecoveryRequired | Lock, повторный запуск, восстановление после сбоя |

Наличие файлов без регистрации не равно установленному продукту; наличие MSI в cache не равно включённому SecureUxTheme. Обнаружение не должно «лечить» состояние записью в реестр.

## 3. Установщик: состояние → действие

Таблица относится к поддерживаемому управляемому продукту без активной операции.

| Фактическое состояние | Карточка | Выбор по умолчанию (предложение) | Отметить | Снять отметку |
|---|---|---|---|---|
| Не установлен, источник проверен | Не установлен / Установить | При первой установке — рекомендуемый набор, см. D2; при обслуживании — не добавлять новые необязательные продукты автоматически | Install | Нет действий |
| Установлен, версия старее, целостность проверяема | Есть обновление | Да | Update | Оставить установленную версию |
| Установлен, версия та же, исправен | Установлено | Нет | Repair с явной подписью «Восстановить» | Оставить |
| Установлен, повреждён, версия не новее доступной | Требуется восстановление | Да | Repair либо Update, если payload новее; в плане точное действие | Оставить повреждённым; ⚠ объясняет последствия |
| Установлена версия новее комплекта | Установлена более новая версия | Нет | Не выполнять downgrade; восстановление только из проверенного источника установленной версии | Оставить |
| Файлы есть, MSI отсутствует | Обнаружены незарегистрированные файлы | Нет | Отдельная миграция после проверки происхождения, не Install поверх неизвестного содержимого | Без изменений |
| Нет полного MSI/источник не прошёл проверку | Нет источника / источник недостоверен | Нет | Install/update/repair заблокированы до восстановления доверенного источника | Без изменений |
| Состояние/контекст не проверены | Не удалось проверить | Нет | Заблокировать изменение этого продукта, объяснить причину | Без изменений |
| Внешний продукт | Внешняя установка | Нет | Не присваивать владение и не менять автоматически | Оставить внешнюю установку |
| Неподдерживаемая ОС/архитектура | Недоступно + причина | Нет | Заблокировано | Нет действий |
| RebootPending | Требуется перезагрузка | Нет | Предложение: блокировать несовместимые операции над затронутым продуктом до перезагрузки | Оставить pending |
| RecoveryRequired | Требуется завершение/восстановление операции | Нет | Сначала recovery по журналу; новый план не строить поверх незавершённого | Сохранить журнал |

**D2 — требуется решение:** рекомендуемый набор первой установки на Windows x64. Предлагается Platform x64 + Platform x86 + GlassSettings + OpenGlass, SecureUxTheme выключен (явный opt-in). Все четыре независимых продукта разрешено снять; отсутствие обеих платформ допустимо. На Windows x86 — только поддерживаемый набор, без x64/OpenGlass. Альтернатива: начинать без предварительного выбора.

«Выбрать всё» отмечает только поддерживаемые, проверенные, доступные действия и необходимые зависимости. Оно не разрешает downgrade, не принимает сертификат разработчика и не меняет внешний продукт. Предложение D2 не изменяет существующее правило запуска OpenGlass: `!filesPresent || wasRunning`.

## 4. Деинсталлятор: состояние → действие

| Состояние/выбор | Отображение | UI-операция | Headless-операция |
|---|---|---|---|
| Установлен, управляемый, не используется как обязательная зависимость | Доступный флажок; снят → «Сохранить» | Remove после итогового плана | Удалить только указанный продукт и разрешённые явно оговорённые составляющие |
| Не установлен | Не включать в список установленных | Нет действия | Идемпотентный успех для известного корректного ID |
| Повреждён | Карточка с ⚠ | Удаление доступно только после проверки MSI identity/контекста/путей и безопасного preflight | Те же проверки; не удалять каталог вместо MSI при ошибке |
| Внешний/непроверяемый | Отдельное пояснение, выбор недоступен | Не менять автоматически | Отказ с диагностикой, не успех |
| Продукт используется сохраняемым продуктом | Замок и объяснение, что требуется сохранить/удалить | Не допускать нарушающий граф итоговый план | Отказать; NoRemove не заменяет проверку engine |
| Удаление после перезагрузки ещё не завершено | Требуется перезагрузка | Не выдавать это за полностью отсутствующий продукт | Вернуть reboot-required, сохранить pending-учёт |
| Другая операция выполняется | Занято | Выбор/выполнение временно недоступны | Код занятости, не параллельное изменение |
| Настройки выбраны без продуктов | «Очистить настройки», отдельное действие | Предложение: разрешить после явного подтверждения scope | Обычная команда удаления продукта это не делает |

Видимая ARP-запись удаляется/обновляется по **факту завершения**, а не сразу после нажатия кнопки. Если часть удаления состоялась, сводка перечисляет удалённое и оставшееся, без ложного «ничего не изменено».

## 5. Матрица совместного выбора

| Запрос | Итоговый план | Предупреждение / ограничение |
|---|---|---|
| Только OpenGlass | Install/update/remove OpenGlass | Платформы и Settings не выбираются |
| Только GlassSettings | Install/update/remove Settings | Не добавлять платформы/OpenGlass автоматически; при удалении учитывать SUT по D1 |
| Удалить Platform x64 | Только Platform x64 | Settings, OpenGlass, x86 остаются; никакого прежнего общего каскада |
| Установить/удалить Platform x86 на Windows x64 | Только x86 | При отсутствии x86 — оформление недоступно 32-битным приложениям; это предупреждение, не блокировка |
| Оставить x86 невыбранной при уже установленной x86 | Keep x86 | Не показывать ложное предупреждение «поддержки нет» лишь из-за снятого флажка обновления |
| Установить SUT, Settings установлен | Install SUT MSI | Проверить совместимость управляющего helper; платформу не добавлять |
| Установить SUT, Settings отсутствует | При D1=да добавить Settings и показать причину/замок | Снятие родительского запроса снимает только добавленную им зависимость, не явный выбор пользователя |
| Удалить SUT, Settings остаётся | Применить штатный стиль → MSI remove SUT | Возможна перезагрузка; Settings не удаляется |
| Удалить Settings, SUT установлен | При D1=да предложить явное совместное удаление Settings+SUT; в UI SUT отмечен с причиной | **D3:** предлагается запретить headless remove Settings, пока SUT установлен, вместо скрытого каскада |
| «Выбрать всё» в установщике | Все доступные действия + нормализация графа | Не выбирать заблокированные/внешние продукты, сертификат и опасные согласия |
| «Выбрать всё» в деинсталляторе | Все доступные управляемые продукты, согласованный полный набор | Не отмечать «Удалить настройки». Не разрешать удаление неизвестного/чужого продукта |
| Снять один продукт после «Выбрать всё» | Перестроить план и проверить граф | Не оставлять выбранный зависимый продукт без prerequisite |

Валидатор строит результат по **послеоперационному состоянию**, не только по галочкам: снятый установленный prerequisite остаётся установленным и может удовлетворять зависимость.

## 6. SecureUxTheme — отдельный автомат состояний

| Состояние | Карточка / допустимое действие | Переход |
|---|---|---|
| MSI сохранён, системный продукт отсутствует | «Подготовлен, не установлен» / установить | Verified MSI → system install |
| Управляемый MSI установлен, активность не подтверждена до перезагрузки | «Ожидает перезагрузки» | Не заявлять, что hook уже загружен |
| Установлен и активен | «Установлено» / удалить или обслужить | Без прямого копирования/удаления System32 из Settings |
| Запрошено удаление | Предупреждение о штатном стиле и перезагрузке | Helper в исходной пользовательской сессии → подтверждённый штатный стиль → MSI remove |
| Helper не применил штатный стиль | Ошибка; продукт остаётся | По умолчанию не продолжать удаление |
| MSI remove вернул 3010 | «Удаление завершится после перезагрузки» | Сохранить pending, не запускать старую cleanup.cmd/task поверх MSI |
| Стиль переключён, MSI remove не удался | Частичный результат: SUT установлен, стиль штатный | Не считать операцию откатанной; восстановление прежнего стиля допускается только после проверки работоспособности SUT |
| Обнаружена чужая установка/конфликт владения | Конфликт, операции недоступны | Никакой автоматической перезаписи/снятия чужой регистрации |

**D4 — открытый технический контракт:** конкретный MSI, миграция perUser/manual → perMachine, direct `msiexec /x`, несколько пользователей/сеансов. Стиль применяется в профиле пользователя, а SUT системный; переключение только в текущей сессии не доказывает безопасность остальных профилей. До решения этих вопросов системную миграцию не выпускать.

## 7. ARP и постоянная оболочка — предложение для утверждения

| Случай | ARP/UI | Engine |
|---|---|---|
| Независимый продукт установлен | «Изменить» + «Удалить» | Modify запускает сохранённую оболочку; Remove headless |
| Используемая обязательная зависимость | «Изменить», удаление скрыто/заблокировано | Повторная проверка reverse dependencies непосредственно перед изменением |
| Продукт отсутствует | Нет видимой продуктовой записи | Controller остаётся, если нужен другим продуктам или recovery |
| QuietUninstallString | Тот же headless remove | UAC возможен; отсутствие мастера не означает обход elevation |
| MSI repair/update вне оболочки | Не должно ломать контракт ARP | Предлагаются собственные visible ARP IDs и скрытые implementation MSI |
| Последний продукт удалён | Убрать принадлежащие Glass записи | Очистка только своего cache после завершения/reboot, не общего Packages |

**D5:** утвердить `%ProgramData%\Packages\GlassPlatform\<version>` как защищённый cache оболочки/полных MSI, separate controller ownership и собственные видимые ARP-записи. Особенности кнопки «Изменить» проверить в классической панели и поддерживаемых Windows Settings.

## 8. Предупреждения и настройки

| Условие | UI | Можно продолжить? |
|---|---|---|
| Platform x86 будет отсутствовать на Windows x64 | Жёлтая карточка, ⚠ под иконкой; полупрозрачное пояснение по клику, закрытие X/вне/Esc; повтор в плане | Да |
| Продукт остаётся повреждённым | ⚠ на продукте, пояснение и план | Да, если выбранные операции безопасны и он не нужен как исправный prerequisite |
| Неизвестная регистрация/чужой системный продукт | Блокировка с причиной | Нет для затронутого продукта |
| Потребуется перезагрузка | Соответствующая метка и итоговый результат | По проверенным условиям MSI, без автоперезагрузки |
| Выбрана очистка настроек | Постоянно видимый отдельный checkbox и явный пункт плана | Только явный выбор, не «Выбрать всё» |

**D6 — scope очистки:** текущая общая операция удаляет GlassPlatform и параметры OpenGlass/DWM текущего пользователя. Предложение сохранить этот scope, но явно предупреждать, что настройки OpenGlass будут сброшены **даже если сам OpenGlass остаётся**. Не удалять сертификат разработчика, темы/личные файлы, чужие профили или логи молча. Очистку запускать после успешного выбранного удаления; при неуспехе пакетов настройки сохранять. Альтернатива — раздельная очистка настроек по продуктам.

## 9. Результаты и обязательные проверки

- Успех без перезагрузки: 0. Успех с требованием перезагрузки: 3010. Занято: 1618. Отмена до изменений: 1602. Dependency/source/conflict/recovery ошибки — документированные отдельные результаты; неизвестные параметры не трактовать как запрос удалить всё.
- Preflight перед изменениями; перед каждым commit перепроверять пути, identity, зависимости и lock. Повторные операции идемпотентны только при проверенном состоянии.
- Multi-MSI удаление не объявлять атомарным: журнал содержит выполненные действия и результат компенсаций. Не маскировать частичный сбой как отмену.
- Сохранять различие явного выбора и автоматически добавленной зависимости. UI не является источником истины; тот же planner вызывается headless worker.
- Тесты: все комбинации пяти продуктов, x86/x64 ОС, все стадии состояния, отсутствие/повреждение cache, downgrade, external SUT, cancel/partial failure/reboot, повторный вызов, несколько сессий и права пользователя.
- Отдельно UI: «Выбрать всё» не меняет cleanup/certificate; изменение prerequisite перестраивает замки; warning доступен клавиатурой; plan и фактические действия совпадают.

## 10. Что согласовать в этой редакции

1. **D1:** SecureUxTheme требует установленный GlassSettings как управляющую зависимость — да/нет?
2. **D2:** рекомендуемый набор первой установки — четыре продукта без SecureUxTheme, или пустой выбор?
3. **D3:** при установленном SUT headless remove Settings запрещён; совместное удаление доступно только через явный UI-план — принять?
4. **D5:** protected ProgramData cache + controller + отдельные visible ARP-записи — принять?
5. **D6:** очистка общая для текущего пользователя, включая OpenGlass даже при сохранении продукта, только по явному выбору и после успешного удаления — принять или разделить по продуктам?

D4 — обязательная техническая проработка выбранного MSI; не перекладывается на пользователя как ручная работа. До её завершения контракт системной установки остаётся проектом.
