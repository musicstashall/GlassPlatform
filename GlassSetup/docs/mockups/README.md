# Макеты GlassSetup

Постоянный каталог макетов: `index.html`. В LIVE PREVIEW он открывается в корне
сервера «Макеты GlassSetup».

Из корня solution:

```sh
python GlassSetup/tools/preview_mockups.py --port 8080
```

Сервер read-only, слушает `0.0.0.0`; адрес браузера — адрес preview, не localhost
другого сервиса. Он отдаёт только этот каталог и `/runtime/` → `GlassSetup/res/` (также `/res/` для относительных
URL старого concept-макета),
проверяет выход за корни и не показывает списки каталогов. Команд системного
обслуживания на сервере нет.

## Содержимое

- **Текущий интерфейс · план и карточки**: настоящий `res/slideshow.html`, а не
  отдельная копия интерфейса. Каталог загружает его в iframe с mock WebView host.
  Только в preview-копии адаптируются virtual-host URL и CSP; production-ресурс
  не меняется ради сервера. `assets/banner.png` соответствует native mapping
  на `res/welcome_banner.png`.
- Выбор Setup/Unins, RU/EN, сценариев обновлений, повреждения, первой установки и
  финальной страницы после удаления, пустых панелей и проверки версии Setup. Версии, размеры, предупреждение и результат
  удаления — **демонстрационные данные**, не результаты обследования компьютера.
- «Удалить всё» меняет только намерения строк; mock host асинхронно подтверждает
  их тем же форматом состояния. Ни MSI, ни native engine не вызываются. Fixture
  не доказывает Windows-транзакцию и не моделирует все её preflight/refusal gates.
- **Предоставленный образец карточки**: `warning-card-reference.png`, исходный
  пример из пользовательского запроса (жёлтый треугольник справа сверху).
- **Концепции A / B / C**: сохранённый `product-maintenance-concepts.html`.

Пример прямого сценария:
`/?app-mode=unins&locale=en&scenario=updates`.

## Проверки

- `tests/maintenance_ui_dom_test.cjs`, `maintenance_entry_dom_test.cjs`,
  `managed_removal_dom_test.cjs`: production DOM через внешний `jsdom@26`.
- `tests/mockups_preview_smoke.cjs`: настоящий Chromium через внешний
  `playwright-core` + `@sparticuz/chromium`; задать `NODE_PATH` и
  `GLASS_PREVIEW_URL` запущенного read-only сервера. В Linux без NSS/NSPR нужны
  соответствующие shared libraries (для Arena использовался комплект `al2023`
  из пакета Chromium с `LD_LIBRARY_PATH=/tmp/al2023/lib`).
- `GLASS_PREVIEW_SCREENSHOT` — необязательный путь снимка вне отслеживаемых
  файлов, например `.cache/glass-ui/mockups-latest.png`.

Проверяются цвета idle/hover и повреждений, popup/Escape/возврат фокуса,
«Удалить всё»/отмена, отсутствие предупреждений в плане, Setup/Unins, RU/EN,
финальная страница, геометрия/центрирование пустых списков, короткий checking copy
и доступность предоставленного образца. Это UI-проверки,
не MSVC/WiX build и не реальное удаление в Windows.

## Версии SecureUxTheme и выделенные карточки

Сценарии `sut-local` / `sut-release` показывают соответственно проверенный локальный
MSI и предложение только из GitHub metadata. Значения MSI 4.0.0 / релиз 4.1.0 —
**демонстрационные**, не live-ответ GitHub. Ссылка «Макеты GlassSetup» остаётся входом
в каталог. Chromium дополнительно проверяет сохранение жёлтого/красного/зелёного
доминирующего цвета при hover и подписи источника версии после выбора установки.

## Панель плана: уточнение уведомлений

В панели — только краткая сводка числа предупреждений и «Подробнее». Полные тексты
находятся в диалоге, а не в строках задач. Это заменяет прежнее правило отсутствия
уведомлений в панели. Кнопка «Принять все рекомендации» выбирает только доступные
обновления, повреждённые продукты или явно рекомендованные позиции; здоровые
переустанавливаются вручную. Красная строка «Удалить все продукты» скрыта, когда
больше нечего добавить к плану удаления. Само удаление по-прежнему только планируется.

## Недоступное удаление SecureUxTheme

`sut-active` и `sut-pending` демонстрируют видимую корзинку-объяснение: нажатие
открывает причину отказа без Remove IPC и изменения плана. Это не разрешение
удаления активного компонента. «Удалить все продукты» при единственном
заблокированном SUT скрыто. Причины и состояния fixture — демонстрационные.
