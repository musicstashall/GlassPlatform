# GlassSettings — конструкция миниатюры атласа

Миниатюра в карточке коллекции (страница «Стилизация») — это собранное «мини-окно»
из частей **активной рамки `DWMWindow`** атласа: полоса заголовка + кнопки
min/max/close. Цель — показать реальный вид темы 1:1 (без произвольного масштаба) на
прозрачном фоне (под миниатюрой видно «стекло» поверх шахматки-индикатора).

## Где код

| Слой | Файл | Роль |
|------|------|------|
| Нативный генератор | `GlassSettings/Native/AtlasPreviewGenerator.{h,cpp}` | парсинг `.layout`, загрузка PNG, композиция превью (WIC) |
| C# оркестрация | `GlassSettings/Services/ThemeImageCatalog.cs` | размеры превью, вызов нативного слоя, кэш |
| XAML-карточка | `GlassSettings/Controls/AtlasImageTile.{xaml,xaml.cs}` | шахматка + «стекло» + изображение |
| «Стекло» (кисть) | `GlassSettings/Resources/PreviewBrushes.xaml` | `PreviewGlassFillBrush` |

## Исходные данные атласа

- **PNG** — один большой лист со всеми частями всех классов темы.
- **`.layout`** — текстовый файл `partId;stateId;propId=l,t,r,b`:
  - `propId=8002` (`TMT_ATLASRECT`) — прямоугольник части в атласе;
  - `propId=3601` (`TMT_SIZINGMARGINS`) — sizing-поля (сейчас в композиции не нужны);
  - `RS1Compatibility=1` — нумерация частей `>10` сдвинута на +1 (приводим к схеме Win10).

Берём **только активную рамку** `DWMWindow` (части 1–91). `INACTIVE/SHADOW/DARK/
SQUEEGEE/SMALL*` — игнорируем. Ключевые ID — в `AtlasPreviewGenerator.h`:

| Часть | ID | Назначение |
|-------|----|-----------|
| `FRAMETOP_ACTIVE` | 46 | полоса заголовка (фон) |
| `MINBUTTON` / `MAXBUTTON` / `CLOSEBUTTON` | 3 / 5 / 7 | фоны кнопок |
| `GLYPH_MIN96` / `GLYPH_MAX96` / `GLYPH_CLOSE96` | 23 / 19 / 11 | символы кнопок (DPI 96) |

## Мультистейт: один прямоугольник = вертикальная полоса состояний

`ATLASRECT` части — это **вертикальная полоса** из N равновысоких срезов:
NORMAL / HOT / PUSHED / DISABLED. `stateId` в layout всегда `0`, поэтому число
состояний определяем **по геометрии** (`DetectStateCount`: делители высоты, срез ≥ 4 px).

Выбор среза для рисования (`NormalOrFallbackStateRect`):
1. берём NORMAL (верхний срез, индекс 0);
2. если он почти пустой (`MeanAlpha ≤ 6`) — fallback на самый непрозрачный срез
   (`MostOpaqueStateRect`). Это спасает темы, где NORMAL прозрачен (напр. The Red Theme).

> Раньше брали самый непрозрачный срез всегда — это давало HOT-состояние с «свечением»
> (другие габариты): кнопки разъезжались и казались ниже. NORMAL фиксит и зазоры, и высоту.

## Семантика кнопок (зависит от темы)

Различаем два типа на лету по непрозрачности фона (`MeanAlpha(bg) > 8`):

- **Стандартные темы** (winxp, AEROTUNE, Win7, …): фон кнопки (3/5/7) видим,
  поверх — мелкий символ-глиф (23/19/11). Ширина ячейки = ширина фона-среза.

> **Порядок и фоны кнопок.** Слева направо: min, max, close. Но в атласах фон `part 3`/
> `part 5` оказались «перепутаны»: скруглённый-слева торец группы лежит в `part 5`, а
> плоский — в `part 3`. Поэтому левой кнопке (min-глиф) даём фон `part 5`, средней
> (max-глиф) — `part 3`; иначе скругление вылезало бы на средней кнопке. Кнопки рисуются
> с инсетом вниз/влево на 2 px, чтобы их кромки не перекрывали кромки шапки.
- **«Лицевые» темы** (Aero Glow …): фон прозрачен, а глиф-часть содержит **всю кнопку**
  с запечённым символом. Рисуем «лицо» в нативном размере (по `ContentBBox`) встык —
  ширина ячейки = ширина лица, иначе появлялись бы зазоры.

## Высота кнопок — два режима (растягивать или нет)

Высота кнопки зависит от того, что лежит в срезе. По горизонтали контент всегда
ставим **по центру ячейки** (шаг = ширина среза) — это убирает слипание кнопок в темах
с несимметричными полями (напр. «Version 2», где MAX прижат вправо, CLOSE влево).
По вертикали — две ситуации, различаемые по геометрии непрозрачного тела (`ContentBBox`):

- **Стеклянная пилюля** (VistaAero, все Win7, win8.1): тело прижато к верху среза
  (`topOff ≤ 2`) и снизу лишь небольшой прозрачный «фартук» (`botSkirt ≤ 40 %` высоты
  среза). Это часть кнопки — её **растягиваем по вертикали** на полную высоту ячейки
  (= высота среза), иначе кнопка выходит вдвое ниже нужного (напр. VistaAero: тело
  15 px в срезе 22 px).
- **Готовая кнопка** (AEROTUNE, XP, Version 2, Bupa): тело уже нужного размера —
  центрировано или с большим намеренным «фартуком». Рисуем в **нативной высоте 1:1**
  без масштабирования; растяжение деформировало бы пиксель-арт.

Формально: `stretchFill = (topOff ≤ 2) && (botSkirt·5 ≤ sliceH·2)`. Ячейка центрируется
по высоте полосы заголовка. Символ-глиф (для стандартных тем) центрируется в реальном
теле кнопки в нативном размере.

## Полоса заголовка (`FRAMETOP`)

`DrawCaptionFill` берёт NORMAL-срез `FRAMETOP` (active 46 / inactive 44).

**По вертикали** — 3-срез по `TMT_SIZINGMARGINS`: `cyTop` / `cyBottom` (тонкие 3D-границы,
оттеняющие линии) рисуются **1:1 по высоте** и не размываются (напр. VistaAero
`cyTop=6, cyBottom=2`); середина по высоте растягивается на высоту полосы.

**По ширине** — поля `cxLeft`/`cxRight` для caption-частей оказались ненадёжны (давали
ложное растяжение боковых краёв и обрезку углов окна), поэтому ширину **не** масштабируем
по полям, а по фактической ширине среза:

- **широкая шапка** (`sw > outWidth`, VistaAero/Win7 = 827 px) — **3-срез**: левый и
  правый углы шириной ≈ высоте среза копируются **1:1** (скруглённые углы окна, активная
  кромка), а центр берётся куском **из середины источника 1:1 (обрезка)** — блики и
  3D-границы чёткие;
- **узкая шапка** (`sw ≤ outWidth`) — левая и правая половины копируются **1:1**, между
  ними растягивается **один центральный пиксель**: арт по краям/углам (winxp-скругления,
  «П»-линии Version 2) не деградирует.

> Превью показывает **только реальное содержимое атласа**. Ничего не имитируется: если
> атлас рисует квадратную шапку (Bupa Dark 3 — FRAMETOP без скруглений; их в окне создаёт
> сама Win11), миниатюра тоже квадратная.

> Полноценный 9-срез по `SIZINGMARGINS` дал регрессию: поля caption-частей описывают не
> то, что нужно для миниатюры (узкие шапки сильно растягивались, у широких обрезался
> левый угол окна). Текущий подход вернул упрощённое центральное растяжение для узких и
> добавил центральную обрезку для широких — без артефактов.

Темы без нарисованной шапки (Version 2 и большинство) имеют узкий `FRAMETOP` из
цветных линий «П» — он так и рисуется (тело окна прозрачно).

`captionHeight = max(высоты ячеек кнопок, высота FRAMETOP)` (не больше высоты холста);
шапка заполняет всю полосу, выравниваясь с кнопками.

## Слои изображения и компоновка

Размер фиксирован (`ThemeImageCatalog`: **170×38 px**), чтобы миниатюры не «гуляли» и
влезали в карточку. Слои (снизу вверх) собираются в нативном `CompositePreview`:

1. **Отражение «стекла»** — PNG-ресурс `102` (тип `"PNG"`) из `OpenGlass.dll`. Берём
   кусок **от верхнего левого угла** без масштабирования (1:1) в `(0,0)`. Угол сильно
   полупрозрачен (alpha ≤ ~22), поэтому даёт лишь мягкий блик и не перекрывает шахматку.
2. **Полоса заголовка** (`FRAMETOP`) — прижата к верху (`yOffset = 0`).
3. **Кнопки + символы** — встык, прижаты **вправо** с небольшим инсетом (вниз и влево на
   2 px), чтобы верхняя/правая кромки кнопок не перекрывали кромки шапки, как в окне.

Низ под полосой — прозрачное «тело» окна (сквозь него видна шахматка и блик отражения).
Все блиты — premultiplied-alpha (`32bpp PBGRA`, WIC), верхние слои смешиваются поверх
нижних. Готовый PNG кэшируется.

> **OpenGlass.dll обязателен.** Путь резолвит `OpenGlassVersionService.ResolveOpenGlassDllPath()`
> (реестр BWM → хардкод → рядом с exe). Если DLL не найдена — миниатюра **не строится**,
> карточка показывает дефолт (штриховка + иконка).

## XAML-карточка и «стекло»

`AtlasImageTile` укладывает в `Grid` поверх друг друга:
1. `CheckerboardImage` — шахматка-индикатор прозрачности (178×92);
2. `PreviewRect` — прямоугольник миниатюры (`AcrylicSubstrate` + `PreviewImage`),
   приподнят по Z (`Translation="0,0,18"`) и отбрасывает `ThemeShadow` на шахматку,
   создавая ощущение парящего над карточкой «стекла»:
   - `AcrylicSubstrate` (`Rectangle`, скругление 4) с заливкой `PreviewGlassFillBrush`;
   - `PreviewImage` — само превью (`Stretch="None"`).

«Стекло» — полупрозрачная заливка (`SolidColorBrush`, напр. `#59AECCE6`), **без размытия**:
сквозь неё читается шахматка. Прозрачность регулируется альфа-каналом цвета кисти в
`PreviewBrushes.xaml` (больше альфа → плотнее стекло). Acrylic с blur не подошёл — на
мелкой шахматке размытие давало ровную серую заливку.

## Карта «частая проблема → причина»

| Симптом | Причина / решение |
|---------|-------------------|
| Кнопки вдвое ниже (VistaAero/Win7/win8.1) | короткая пилюля, прижата к верху → растягиваем до высоты среза |
| Деформация кнопок (AEROTUNE/XP/Version 2/Bupa) | пиксель-арт нельзя тянуть → рисуем 1:1 (тело центрировано / большой «фартук») |
| Кнопки разъезжаются с зазорами | брали HOT-срез (со свечением) → берём NORMAL |
| Слипание двух кнопок («Version 2») | несимметричные поля → контент по центру ячейки |
| Размытые блики/потерянные скругления шапки | сжатие широкой шапки по ширине → 3-срез (углы 1:1 + центр-обрезка) для широких / половины 1:1 + центральный пиксель для узких |
| Скругление вылезает на средней кнопке | фоны `part 3`/`part 5` перепутаны → левой кнопке фон `part 5`, средней `part 3` |
| Ожидается «козырёк»/скругление, а шапка квадратная | это реальный атлас (FRAMETOP без скруглений); ничего не имитируем — превью = содержимое атласа |
| Шапка растягивается вместе с боковыми краями | растягивание по полям `cxLeft/cxRight` caption-частей (ненадёжны) → ширина по фактическому срезу, без полей |
| Кнопки перекрывают верх/правый край шапки | нет инсета → сдвиг кнопок вниз и влево на 2 px |
| Кнопка пустая (The Red Theme) | NORMAL прозрачен → fallback на самый непрозрачный срез |
| «Стекло» не видно | малая альфа `PreviewGlassFillBrush` → увеличить альфу цвета |
