# Текстурные отражения

Коллекция `Resources/GlassReflection` разделена на `Textured` (плитки) и
`Pattern` (цельные изображения). Старые изображения непосредственно в корне
по-прежнему поддерживаются. Каталог `Tests` не включается в UI.
Имена исходников должны быть уникальны среди текстур; размеры в именах не нужны.

## Подготовленные узоры

- `GlassReflection_01`: исходник увеличен пропорционально до 121,9048%,
  из левого верхнего угла вырезано 256×256.
- `GlassReflection_02`: фрагмент 160×160 с позиции (1, 0) увеличен до
  256×256 (160%). Первый столбец оригинала содержит отклонения от узора
  и исключён. Оставшийся рисунок имеет точный период 5×5 пикселей.
  При линейном увеличении используется периодическое окружение фрагмента
  (повторение без зеркалирования), чтобы фильтр не создавал краевые артефакты.
  Результат имеет точный период 8×8 пикселей — 32 повтора в плитке.
  В коллекции хранится только одна ячейка 8×8 из этого результата, без
  повторного ресэмплинга. Тест проверяет минимальность периода и SHA256
  полноразмерных полотен обеих тем относительно согласованных плиток 256×256.
- У `01` меньший точный период, позволяющий заменить нынешнюю плитку без
  изменения полотна, не найден. Она оставлена 256×256.

Карточки отражений используют TransparencyCheckerboard, как коллекция атласов.
Миниатюры Textured формируются повторением исходника до 148×92, без увеличения
ячейки. Используется тот же алгоритм копирования пикселей, что для полотна;
для XAML данные декодируются с premultiplied alpha. Pattern и остальные
изображения продолжают показываться прежним способом.

Обе пары пересозданы из загруженных оригиналов. При увеличении используется
линейный фильтр Triangle вместо nearest-neighbor, чтобы избежать грубой
репликации микропикселей. Никакого зеркалирования, растяжения по одной оси
или ретуши краёв. Для 01 масштаб близок к запрошенным 120%; для 02 увеличен до 160%
по дополнительному запросу пользователя. У 01 абсолютная бесшовность не гарантируется.
Dark — чёрный RGB, Lite — светло-серый #D0D0D0, альфа попарно одинаковая.
Цвет Lite изменён и у Pattern/PearlDiagonal; прозрачность не менялась.

## Применение

`ReflectionTextureService` собирает PNG точным копированием пикселей плитки.
Краевые неполные плитки обрезаются. Размер берётся из SM_CXVIRTUALSCREEN /
SM_CYVIRTUALSCREEN, поскольку OpenGlass масштабирует отражение на виртуальный стол.
PNG сохраняется в `%LOCALAPPDATA%/GlassPlatform/GlassReflection/<ширина>x<высота>/`
под исходным именем. Соседний `.sha256` хранит хеш источника и версию алгоритма.
Этот путь — только внутренний кэш и больше не передаётся OpenGlass.
Готовое полотно копируется под исходным именем непосредственно в
`%PROGRAMDATA%/OpenGlass/Presets/Textured/` (без подпапки разрешения).
Перед каждым копированием, в том числе при попадании в кэш, очищается содержимое
только `Presets/Textured`, включая старые подпапки. Остальные пресеты не затрагиваются.
При обнаружении junction/symlink очистка отменяется. Запись выполняется через
временный файл и переименование. В реестр записывается абсолютный путь новой копии
только после успешного завершения. При отказе доступа/ошибке копирования UI
показывает сообщение; повышения прав или изменения ACL автоматически нет.
Одновременно сохраняется только одно применяемое полотно: переключение текстуры
удаляет предыдущую общую копию, в том числе выбранную в другой DWM-партиции.
Это соответствует политике обязательной очистки, а не отдельному кэшу на тему. Ограничения размера соответствуют проверкам PNG
upstream OpenGlass (16384 по стороне, 33554432 пикселя).

Генерация сериализована, заполнение полотна выполняется вне UI-потока.
Операция выбора проходит через page operation pipeline. Для выделения и защиты
активного исходника от удаления путь к внутреннему кэшу или Presets/Textured сопоставляется с Textured по имени.
Произвольные PNG вне каталога кэша так не сопоставляются.

## Текущее ограничение

Размер экрана проверяется при выборе текстуры. Автоматическое переприменение
после изменения конфигурации мониторов, без повторного выбора пользователем,
пока не подключено. Пересборка и runtime-проверка WinUI требуют Windows.

## Проверка предполагаемого периода 01

Для исходника пользователя проверены смещения 15 по X и 13 по Y в верхней
левой области 256×256. По X отличались 203 из 61696 пар (максимум 2 уровня
альфы), по Y — 55645 из 62208 пар (максимум 28 уровней). Таким образом, 15×13
описывает приблизительный, но не точный повтор. 01 оставлена без обрезки
до такой ячейки, чтобы не вносить новый разрыв и не менять согласованный масштаб.
