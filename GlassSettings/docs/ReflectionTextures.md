# Отражения: PNG-плитки, SVG и генерация полотна

Актуальная реализация GlassSettings. Исходники находятся в
`OpenGlass/Resources/GlassReflection`, поставляются пакетом OpenGlass Resources;
пользовательский PNG для OpenGlass формируется отдельно в ProgramData.

## Источники и коллекция

| Pivot | Источник | Применение |
|---|---|---|
| Текстуры | `Textured/*.png` | Маленькая RGBA-ячейка замощения; повторяется до размеров виртуального рабочего стола |
| Рисунок | `Pattern/*.svg` | Самостоятельная векторная композиция, растеризуется в PNG; здесь же «По умолчанию» |
| Другие | Растровые изображения в корне `GlassReflection` | Применяются как есть, без генератора и диалога обработки |

Прежние растровые Pattern поддерживаются прежним путём, но не получают SVG-настройки.
Каталог Tests не включается в коллекцию. Переключение категории не пишет в DWM;
при загрузке страницы выбирается категория активного исходника. «Настроить»
доступно для выбранной текстуры/SVG, не для стандартного отражения и passthrough.
Имена исходников должны быть уникальны между генерируемыми категориями: итоговое
имя — имя исходника с расширением `.png`, без добавленных размеров.

### Пиксельные текстуры

При масштабе 100% пиксели копируются в нативном размере: нет растяжения маленькой
плитки на весь экран, зеркалирования или выдуманного центрального кропа.
Правый/нижний остаток холста заполняется частичным повтором ячейки. Только явный
масштаб пользователя меняет размер ячейки, с округлением и alpha-aware bilinear
пересчётом. Мягкость рассчитывается с периодическим окружением ячейки; шум
добавляется уже после замощения на **весь** холст.

У каждого узора теперь один источник без суффикса темы. При консолидации
сохранён побитово прежний Dark-источник, поэтому утверждённые альфа и геометрия
не изменены. RGB исходника больше не определяет результат: генератор окрашивает
альфа-паттерн цветом из пикера. Пресеты Dark #000000 и Light #A0A0A0 заменяют
прежнее хранение двух файлов. Утверждённые текстуры: FrostWeave, DiagonalWeave, MicroBasket, FineDiagonal,
DragonScale, MicroChevron, CircuitMaze, CrossStitch, TwillWeave. CircuitMaze
имеет согласованное мягкое периодическое сглаживание. Периодические проверки
сами по себе не доказывают визуальную бесшовность в OpenGlass.

Подготовка исходных 01/02 (не путать с масштабом пользователя):
- FrostWeave, ранее GlassReflection_01: ячейка 15×13 от (0, 63), увеличенная
  до 21×18 — X 140%, Y 138,46% с округлением. Различия альфы в повторяющихся
  сегментах оригинала приняты за артефакты пересохранения; рисунок не зеркалится.
- DiagonalWeave, ранее GlassReflection_02: ячейка 5×5 от (1, 0), увеличенная
  до 8×8 (160%, а не 200%). Исключён аномальный первый столбец оригинала.
  Это соответствует переходу 1200×675 → 1920×1080.

Старые каталоги и имена Dark/Lite, 01/02 не сопоставляются и не мигрируются.
`ResolveSource` распознаёт только текущий опубликованный PNG в `Presets\Textured`
по валидной State-записи и её точному пути Source. Цвет берётся из ColorRgb,
а не выводится из имени файла. Старые DWM-пути автоматически не переписываются.

### Векторные рисунки

Самостоятельные единые SVG-источники: SilkWave, FoldedVeil, CornerGlow, PrismGlints,
LiquidCaustics. Это реальные векторы без встроенных растровых изображений;
геометрия и прозрачность взяты из утверждённых исходников без изменения. `viewBox` и
`preserveAspectRatio` определяют растеризацию; текущие композиции используют
1920×1080 и `none` для заполнения холста. Пользовательский масштаб применяется
от центра, при уменьшении остаются прозрачные поля. Мягкость ограничивается
краями холста, не заворачивается на противоположный край.

Рендерер — SVG.NET (`Svg` 3.4.7, System.Drawing, Windows). Профиль ограничен:
контуры, простые фигуры, группы, градиенты, clipPath, заливки и прозрачность.
Запрещены DTD, processing instructions, CSS, скрипты, шрифты/текст, image,
use/href, фильтры и внешние ресурсы. XML resolver отключён; до передачи в
SVG.NET проверяются положительные списки элементов/атрибутов. Ограничения:
256 KiB исходника, 512 элементов, глубина 32. SVG вне Pattern не включаются
в коллекции материалов или атласов. SVG напрямую в OpenGlass не передаётся.

## Диалог обработки

Целевая ширина hosted-диалога следует пропорциям превью: 280 DIP × отношение
ширины virtual desktop к высоте + 64 DIP на отступы, в пределах 480–1120 DIP.
Она не вычисляется из ширины root-окна/монитора. Shell только ограничивает её
доступным местом. Один 16:9 монитор даёт около 562 DIP, два рядом — около 1060.
Колонка параметров ограничена 340 DIP, а не растягивается на всё свободное место. Сверху на всю ширину — пропорциональное превью desktop
(высота до 280px). Под ним master toggle.
Ниже слева группы Pivot **Изображение** и **Шум**, справа группа **Цвет**:
четыре пресетные плашки `AccentRecentColorSwatch` (тот же контрол, что на странице «Цвета»)
(тёмная, светлая, текущий акцент Windows, пользовательский цвет), история цветов и кнопка **Посмотреть цвета**. Галочка отмечает точное совпадение выбранного ARGB
с пресетом или цветом истории; произвольный цвет без совпадений не отмечен.
Кнопка открывает Flyout со стандартным `GlassAlphaColorPicker`: оттенок,
яркость, HEX и альфа. При ширине тела от 960 DIP кнопка скрывается, тот же
экземпляр пикера переносится в правую колонку рядом с вертикальными пресетами.
При сужении возвращается во Flyout. Размеры/шаблон пикера не изменяются. Flyout закрывается
при закрытии родительского диалога; изменения сохраняются только по «Применить».
Общий размер заголовков Pivot 14.
Выбранная группа запоминается только на время жизни процесса, включая отмену
и закрытие крестиком; восстанавливается после Loaded Pivot. Числовые поля
используют `GlassSettingsNumberBoxStyle` и Inline «− / +», как Popup → Анимация.

| Параметр | Диапазон / поведение |
|---|---|
| Масштаб | 25–200%, по умолчанию 100% |
| Цвет / яркость / оттенок | RGB из пикера, по умолчанию #000000; альфа паттерна сохраняется |
| Непрозрачность | Альфа пикера 0–255 переводится в существующий параметр 0–100%; применяется к рисунку вместе с шумом |
| Мягкость краёв | 0–20 px, по умолчанию 0; alpha-aware фильтрация цветов без тёмных ореолов |
| Тип шума | Без шума / Мягкое / Плёночное / Точечное / Блочное / Мелкозернистое |
| Интенсивность шума | 0–100%, по умолчанию 0; сила слоя |
| Плотность зерна | 0–100%, по умолчанию 50; доля активных зёрен, не увеличение их размера |

**Без шума** отключает интенсивность/плотность в UI и исключает их из рендера,
но сохраняет введённые значения. Параметры изображения продолжают применяться.
**Применять обработку** отключает вообще все эффекты, сохраняя их значения:
текстура нативно замощается, SVG растеризуется без дополнительных эффектов.
Плашки **Для тёмной темы** / **Для светлой темы** в группе «Цвет» заменяют
отдельную «По умолчанию»: включают обработку и восстанавливают весь рецепт
(масштаб 100%, мягкость/шум 0, без шума, плотность 50) с цветом
#000000 / #A0A0A0 и альфой 100%. Они доступны и при bypass как действие сброса;
редактирование пикера/вкладок при bypass заблокировано.
**Отмена/крестик** ничего не публикуют; **Применить** передаёт настройки в
существующий serial-конвейер страницы. Recipe/PNG в самом диалоге не публикуются;
по «Применить» отдельно запоминается ограниченная история цветов.

### Превью виртуального рабочего стола и обои

`ReflectionDesktopPreview` получает реальные `DisplayArea.OuterBounds` и сохраняет
взаимное расположение мониторов, отрицательные координаты и пропорции общего
виртуального экрана. Два соседних монитора — два соседних прямоугольника; если
мониторы стоят вертикально/со смещением, показано именно это расположение. Общий
Canvas пропорционально уменьшается Viewbox, а не растягивается в фиксированные
16:9. Рисунок — одно полотно: каждый монитор показывает соответствующий фрагмент,
а не отдельную повторённую SVG-композицию. У мониторов есть кант, скругление и тень.
В промежутках между мониторами отражение не рисуется. Топология фиксируется при
открытии диалога; после переподключения дисплеев диалог следует открыть заново.

Шахматка удалена. Используются **существующие** `DesktopEnvironmentWatcher.Current`,
`DesktopWallpaperImageCache.BeginLoad/LoadTask/GetDisplaySourceOrLoad` и
`WallpaperPreviewCrossfade` (500ms). MainWindow владеет инвалидированием кеша;
новый watcher, polling, чтение реестра/файлов обоев и декодер в диалог не добавлены.
Общий COM-адаптер `DesktopWallpaperCom.ReadMonitorWallpapers` и расширение
`DesktopWallpaperImageCache.GetMonitorDisplaySourcesAsync` возвращают bitmap
для каждого монитора, включая разные фотографии. Они используют те же read/decode
helpers и общую инвалидацию; COM-указатели освобождаются. При недоступном COM
используется общий display bitmap; пустой per-monitor путь означает сплошной фон,
а не старую фотографию. Точный Windows Span/Tile/Center fit пока не воспроизводится:
фотография заполняет свой монитор через UniformToFill.

Порядок в каждом прямоугольнике **плоский: обои → стекло → отражение**. Между этими
слоями нет inset, смещения, каскада, отдельных карточек или подписей. Стекло
`FlatGlassPreviewLayer` использует тот же `CompositionWallpaperPipelineBuilder`
и активное Vista/Win7-состояние `CompositionPreviewRegistryStates.BuildRuntimeActive`,
что «Стилизация»: blur → Win7 afterglow → tint → opaque overlay. Это не новый
алгоритм blur/смешивания. Конвертация snapshot в WriteableBitmap также общая.
Коэффициент отображения отражения (0.5 × runtime intensity) вынесен в общий
`RuntimeReflectionOpacity`; в создаваемый PNG этот preview-коэффициент не входит.
Материал/атлас в диалог не добавляются.

После события обоев ожидаются актуальные bitmap/стекло; только после подготовки
стекла начинается синхронный wallpaper crossfade, PNG отражения не перерендеривается.
Смена темы/accent также обновляет factual glass. Подписка снимается при закрытии,
устаревшие async обновления и crossfade очищаются.

Живой рендер использует реальные размеры виртуального экрана, а не 384×216,
поэтому масштаб плитки/зерна соответствует финальному PNG. Рендеры сериализованы
отдельным semaphore с debounce и revision guard: во время изменения пикера
старые запросы не накапливают параллельные большие PNG. На больших конфигурациях
мониторов это дороже маленькой миниатюры. Ничего не публикуется до «Применить».
Миниатюры коллекции по-прежнему имеют ровную подложку #909090 и нативное
повторение текстур 148×92; атласы не изменены.

Шапка спойлера следует [общей политике адаптации](GlassSettings-adaptive-layout.md):
«Настроить» слева от слайдера, трек 120–200 px. После переноса таблицы под
заголовок остаётся единый бюджет ширины. При недостатке места для суммы минимумов
`StackFixedActionBelowSlider` переносит кнопку ниже слайдера на третью строку;
возврат идёт в обратном порядке с гистерезисом 1 px. Пороги измеряются общей
таблицей, страница не содержит собственного resize-конвейера.

### Типы шума

Шум — независимый ахроматический слой по всему холсту, включая прозрачные пиксели.
Он не наследует цвет рисунка. Поле g ∈ [−1, 1] задаёт яркость 127.5×(1+g),
а альфа — |g|×интенсивность/100×0.35×коэффициент типа. Почти нейтральные зёрна
прозрачны, а не образуют равномерную серую заливку. Композиция source-over
в straight BGRA предшествует общей непрозрачности. Рендер детерминирован.

| Сохранённый ID | Тип | Характер |
|---|---|---|
| −1 | Без шума | Пропуск шума независимо от интенсивности и плотности; значение по умолчанию |
| 0 | Мягкое | Плавная интерполяция равномерного поля, характерный шаг 2 px |
| 1 | Плёночное | Смесь масштабов 2/1 px, гауссовы отсчёты Box–Muller, ограничение ±2.5σ |
| 2 | Точечное | Отдельные смещённые круглые зёрна в сетке 3 px; покрытие 2×2 субпикселя |
| 3 | Блочное | Намеренные квадратные фракции 2×2 px |
| 4 | Мелкозернистое | Независимые пиксели шести яркостей, без интерполяции; ранее «Наждачный» |

Типы оставлены раздельными: общая интерполяция мягкого/плёночного не означает
одинаковое распределение или спектр. Плёночный тип — стилизация, не физическая
модель фотоплёнки. Плотность выбирает кандидатов зёрен отдельным hash; процент
покрытия зависит от формы и перекрытий и не обязан равняться параметру.

Сила пяти типов согласуется по sqrt(mean(g^4)) на поле 96×96 при полной
плотности, что учитывает совместное влияние яркости и альфы. Более сильные
типы ослабляются до самого слабого, не усиливаются и не клипуются. Это не
обещание одинакового восприятия на любом фоне или при любой плотности.

Мелкозернистое основано на анализе пользовательского NoiseAsset_256x256_PNG.png:
яркости 0/51/102/153/204/255 с количествами 1311/9094/22034/22214/9351/1532.
Средняя 128.30, σ=52.83, горизонтальная корреляция ≈−0.018. Генерируется новое
поле с этим распределением, а не плитка из загруженного файла. Это не обещание
совпадения с материалом OpenGlass, у которого другой контекст композиции.

## Генерация, публикация и состояние

1. `ReflectionTextureService.PrepareAsync` сериализует генерации SemaphoreSlim.
2. Размер — виртуальный рабочий стол SM_CXVIRTUALSCREEN/SM_CYVIRTUALSCREEN;
   стороны не больше 16384, площадь не больше 33554432 пикселей.
3. Проверяется SHA256 источника до/после рендера. PNG-текстуры ограничены
   1024×1024 до пользовательского масштаба. Рендер формирует straight BGRA PNG.
4. Промежуточный файл находится только в
   уникальной папке `%TEMP%\GlassPlatform-Reflection-<случайный суффикс>`;
   временные файлы, staging PNG и сама папка удаляются в finally (также при ошибке). Это не публичный путь для OpenGlass.
5. HKCU-состояние инвалидируется. Итоговый PNG (до 64 MiB, путь короче MAX_PATH)
   публикуется **для PNG и SVG в один каталог**:
   **`%PROGRAMDATA%\OpenGlass\Presets\Textured\`**.
6. Перед копированием очищается только этот каталог, включая его подпапки.
   Запись идёт через временный файл/переименование; после успеха остаётся один PNG.
   Reparse points в пути и содержимом отвергаются. Другие Presets и исходники
   не очищаются. Этот каталог — выделенная область генератора: личные файлы
   хранить в нём нельзя.
7. После публикации сохраняется готовое состояние, затем DWM-путь изменяется
   в [page operation pipeline](GlassSettings-page-pipeline.md):
   RegistryMutation → Cosmetic → NoticeSync (Animating при необходимости).

Рендер выполняется заново при применении; старого кеширования по `.sha256` нет.
Удаление предыдущего файла перед публикацией означает, что ошибка после очистки
может оставить каталог пустым: атомарность всей замены и rollback не заявляются.
При ошибке состояние не объявляется готовым, показывается локализованная ошибка.

Состояние последнего PNG: **HKCU\Software\StanislavKa\GlassPlatform\GlassSettings\Textured**,
значение **State**, REG_SZ JSON. Поля: Version=1, Ready, Source, Output, Width,
Height, SourceHash, OutputHash, Settings. Settings включает ScalePercent,
OpacityPercent, Softness, NoisePercent, NoiseType, NoiseDensity, Enabled, ColorRgb
(RGB без альфы, по умолчанию чёрный).
Прежний NoiseSize оставлен для чтения совместимых записей, игнорируется рендером
и нормализуется в 1. При вставке «Без шума» старые ID 0..4 не перенумерованы;
индекс ComboBox равен ID+1. Это одна запись последнего результата, не профиль
каждого исходника; JSON-файлы и metadata PNG не используются. При чтении
проверяется SHA256 результата, чтобы не принять чужой PNG за свой рецепт.

## Права доступа и безопасность ProgramData

GlassSettings **не повышает права автоматически и не изменяет ACL**. Сам путь
ProgramData не гарантирует возможность обычной записи в существующий каталог.
Для выполнения генерации учётной записи процесса требуются:

- чтение исходных ресурсов и право записи/удаления в пользовательский TEMP;
- создание/запись State в указанном разделе **собственного HKCU**;
- traverse/read на родительских каталогах ProgramData/OpenGlass/Presets;
- если Textured ещё нет — право создать подкаталог в Presets;
- для существующего Textured — перечисление и чтение, создание/запись файлов
  и подкаталогов, переименование, удаление всех прежних файлов/подкаталогов.
  Практически это **Modify («Изменение») на Textured с наследованием на файлы
  и подпапки**; одной Write («Запись») недостаточно из-за обязательной очистки.
- процессам OpenGlass/DWM, читающим результат, — Read и traverse к финальному PNG.

Полный доступ/смена владельца/DACL для обычного рендера не нужны. Не следует
выдавать запись на весь ProgramData, бинарники OpenGlass, каталог пакетов Setup
или всю коллекцию исходников. ACL, если они требуются для обычных пользователей,
должны быть ограничены выделенной генерируемой папкой и управляться установкой/
администратором. В текущем OpenGlass Resources MSI явной настройки ACL для
`Presets\Textured` нет: **нельзя утверждать, что Modify уже выдан установщиком**.
Унаследованные права конкретной установки следует проверять отдельно. Запуск
из Build этих требований не отменяет. При AccessDenied применяется обычная
ошибка генерации; обхода в LocalAppData и скрытого UAC-запуска нет.

ProgramData общий для пользователей, HKCU индивидуален. Один пользователь может
заменить последний PNG другого; проверка хеша выявляет несоответствие, но не
создаёт изоляцию пользователей. SemaphoreSlim защищает только этот процесс:
межпроцессная/межпользовательская блокировка не реализована. Новый PNG заменяет
предыдущий и для других DWM-партиций. Откат DWM-снимка не возвращает старое полотно.
Автоматическая регенерация при смене конфигурации мониторов пока не подключена.

### Диагностика открытия диалога (Debug)

В Output Visual Studio этапы открытия помечаются `[ReflectionConfigure]`:
click → settings → picker → desktop snapshot/cards → render → hosted dialog,
а после Loaded — загрузка wallpaper sources. Обработчик
кнопки выводит полное managed exception и повторно бросает его для штатной
диагностики (ошибка не маскируется под Cancel). Native FailFast этими catch
не перехватывается: для него необходимы код исключения/стек отладчика или дамп.

Полученный журнал GlassSettings.txt до нажатия «Настроить» на Debug x64 с
ed2a5ac содержит успешную генерацию/декодирование AtlasPreview, но не содержит
исключения или следа открытия reflection dialog. Он не устанавливает причину
повторного падения; предыдущий стек про WinRT IEnumerable к нему автоматически
не относится.

Повторный Debug-лог после 0950093 подтверждает завершение monitor snapshot
(count=1, 1920×1080), создания диалога и Loaded composition clip. Последняя
запись — `wallpaper: read monitor sources`; возврат per-monitor источников не
подтверждён. В COM-адаптер добавлены маркеры каждого вызова и освобождения
ресурсов, в общем кеше — маркеры ожидания bitmap. Конкретный упавший вызов
пока не установлен; эти изменения диагностические, не исправление причины.

Следующий пользовательский лог с d356aa7 подтверждает все COM-вызовы,
освобождение указателей и RCW (`wallpaper COM: complete`). Последняя запись —
`wallpaper cache: await monitor bitmap`, без `monitor bitmap ready`.
Это локализует незавершённую async-операцию, но не доказывает место падения:
в это время также может выполняться отложенный render/decode отражения.
Добавлены отдельные Debug-маркеры read/decode wallpaper и render/decode reflection.

После включения first-chance диагностики пользователь поймал
ArgumentOutOfRangeException непосредственно в DisplayArea.FindAll. Этот API
удалён из ReflectionDesktopPreview: геометрия теперь читается через Win32
EnumDisplayMonitors (полные прямоугольники, включая отрицательные координаты),
дальнейшая раскладка использует managed-массив. Это устраняет данный WinRT-путь,
но тождество first-chance исключения и прежнего завершения процесса ещё не
подтверждено; необходима повторная проверка диалога в Windows.

### Разбор Stowed Exception и исправление клипа

WinDbg для пользовательского дампа показал `STOWED_EXCEPTION_80004002` /
`E_NOINTERFACE` в `Microsoft.UI.Xaml!HWCompTreeNodeWinRT::UpdateVisualClipAndTransform`
(WinUI 3.2.1.0), затем FailFast `0xC000027B` при отправке кадра compositor.
Это не стек чтения wallpaper. Из preview удалено прямое назначение
`CompositionGeometricClip` через `GetElementVisual(layers).Clip`: оно конфликтует
с обработкой clip у XAML-owned visual. Обрезка полного desktop canvas по монитору
остаётся штатной XAML `RectangleGeometry`; рамка Border сохраняет CornerRadius
и тень. Отдельная rounded composition-маска содержимого больше не создаётся.
Исправление требует пользовательской runtime-проверки; дамп локализовал render
clip, но локальное воспроизведение на Windows здесь не выполнялось.

После пользовательского подтверждения открытия диалога удалена отдельная кнопка
сброса, редакторы перенесены под полноширинное preview. Для предотвращения муара
готовое полотно полного virtual desktop предварительно уменьшается WIC Fant
до физического размера preview (ActualWidth/Height × RasterizationScale), а не
передаётся напрямую GPU для сильного уменьшения мелких повторяющихся ячеек.
При изменении размера preview миниатюра пересчитывается через прежний debounce
и semaphore. ProgramData PNG остаётся полноразмерным; downsample только для UI.

### Компоновка А

Редакторы под превью выровнены по верхнему краю (Pivot больше не центрируется
по высоте большого пикера). Правая колонка 280px; заголовок BodyStrong вместо
Subtitle. Только в reflection dialog вызывается `UseCompactLayout` общего
пикера: спектр высотой 140px, HEX и слайдеры доступны без кнопки «Дополнительно».
Другие потребители пикера остаются без изменений. Геометрия мониторов сохранена.

Исправлены отсутствовавшие подключения Click у обеих кнопок пресетов.
Проверка теперь требует именно подписки darkPreset/lightPreset, а не только
наличия функции ApplyPreset. Runtime-оценка компактной компоновки — в Windows.

### Текущий масштаб превью и загрузка

По уточнению пользователя PNG-текстуры в preview замощаются при выбранном
ScalePercent в пикселях миниатюры, без уменьшения ячейки вместе с монитором.
Их RenderConfiguredAsync получает размеры отображаемого preview с учётом DPI.
SVG рендерится на полный virtual desktop и уменьшается до preview через WIC
Fant. Финальный публикуемый PNG в обоих случаях остаётся полноразмерным.

До завершения первой подготовки wallpaper/glass и reflection desktop view
невидим (место зарезервировано), отображается ProgressRing. Это исключает
показ промежуточного чёрного слоя. При ошибке отражения показывается ошибка
и доступная подложка, а не бесконечный индикатор. При последующих изменениях
сохраняется предыдущий кадр. Эксперимент UseCompactLayout/ResizeSpectrum удалён.

### Акцент, история и ярлычок

Акцентный пресет использует WindowsPersonalizationService.ReadUserAccentColor
(тот же источник, что «Цвета»), обновляется на ThemeChanged/AccentChanged общего
DesktopEnvironmentWatcher. Плашка обновляется без незапрошенной замены выбранного
цвета отражения; подписка снимается при закрытии.

Четвёртая плашка хранит последний пользовательский ARGB из пикера. До выбора
пользовательского цвета она неактивна. Выбор встроенного пресета не затирает её.
При выборе другого пользовательского цвета предыдущий custom переходит в историю,
а новый занимает четвёртую плашку. Выбор цвета из истории аналогично поднимает
его в custom. Галочка учитывает альфу.

История содержит до восьми уникальных выбранных здесь ARGB; цвета всех текущих
пресетных плашек из неё исключаются (в том числе custom и live-акцент). При
изменении акцента фильтр обновляется. Импорта Windows recent accent colors нет.
По «Применить» история перезаписывается целиком (`RecentColors`, REG_MULTI_SZ),
custom хранится отдельно (`CustomColor`, DWORD) в существующем HKCU Textured.
Изменения до «Применить» локальны; отмена не записывает историю или custom.
Системный акцент и его история не изменяются.

Имя источника удалено из отдельной строки. Preview показывает компактный
ярлычок поверх верхней части с theme-aware фоном, тонкой рамкой, скруглением
и ellipsis. Ярлычок появляется вместе с подготовленным превью, без вмешательства
в Composition clip.

### Узкая компоновка

При ширине тела <620 DIP плашки пресетов располагаются вертикально, история
тоже перестраивается в одну колонку. Ширина панели цвета 164 DIP, параметрам
выделяется оставшийся бюджет без принудительного минимума 260 DIP. При <480 DIP
панель цвета переходит во вторую строку под параметрами. При >=960 DIP остаётся
стандартный inline-пикер; на меньшей ширине — Flyout. Подпись «Недавно
использованные цвета» удалена; сами плашки истории сохраняются.

### Четвёртая плашка как кнопка пикера

Отдельная «Посмотреть цвета» удалена. Четвёртая плашка всегда доступна и
открывает стандартный Flyout по клику; если пикер уже inline — переводит на
него фокус. Пикер получает цвет этой плашки. Начальное значение: сохранённый
custom, иначе первый цвет собственной истории, иначе текущий default пикера;
текущий нестандартный цвет рецепта имеет приоритет. Цвета встроенных пресетов
не сбрасывают custom в пустое/неактивное состояние.

Плашки выровнены слева; вертикальная панель занимает 56 DIP, горизонтальная
216 DIP. Подпись мягкости сокращена до «Размытие, px» / «Blur, px», диапазон
0–20 сохранён в NumberBox и нормализации. Это заменяет прежнюю длинную подпись
с диапазоном, переносившуюся на две строки.

### Распределение доступной ширины редакторов

Пресеты теперь Grid с 1/2/4 колонками (ячейки 48 DIP, промежутки 8 DIP), а не
StackPanel с переключением ориентации. История использует такое же число колонок.
Колонка параметров — star, с MaxWidth 420 DIP: она использует свободное место,
а панель цвета выравнивается справа. Для расчёта сетки резервируется 320 DIP
параметрам и 16 DIP между колонками. Inline-пикер включается только если
помещается его измеренная стандартная DesiredSize.Width (минимум бюджета 300 DIP)
вместе с параметрами, одной колонкой плашек и промежутками. После выделения
места пикеру остаток определяет число колонок плашек. При ширине <380 DIP цвет
переносится под параметры. Прежние фиксированные пороги inline 960 DIP и
вертикали 620 DIP больше не применяются. Размер превью и правила его рендера
не изменены. Runtime-оценка переходов требуется на Windows.

### Итоговая палитра: пресеты, четыре недавних цвета, кнопка пикера

Цветная custom-плашка заменена обычной theme-aware кнопкой 48×48 с FontIcon
Color (E790) и tooltip «Выбрать пользовательский цвет». Она не окрашивается
текущим цветом и не получает галочку. Кнопка всегда последняя в общей сетке:
три встроенных пресета → 0–4 недавних пользовательских цвета → кнопка пикера.
Таким образом, максимум восемь плиток; фиксированной «четвёртой позиции» больше нет.

Текущий пользовательский цвет теперь входит в историю и отмечается там галочкой;
исключаются только цвета трёх встроенных пресетов. Выбор нового цвета перемещает
его в начало истории, сохраняется максимум четыре уникальных ARGB. CustomColor
остаётся памятью начального цвета пикера, а не отдельной цветной кнопкой.
Одна сетка раскладывает все плитки в 1/2/4 колонки без разрыва между пресетами,
историей и кнопкой. Во время редактирования Flyout его кнопка не удаляется из
visual tree: обновляются только плашки истории, вставляемые перед последней кнопкой.

### История только после явного «Применить»

ColorChanged пикера и выбор существующей плашки меняют только pending color,
галочки и preview. Во время жестов история не пополняется и не перестраивается.
Только ветка HostedDialogResult.Primary добавляет итоговый нестандартный ARGB
в начало списка, убирает дубликаты/встроенные пресеты, ограничивает список четырьмя
цветами и сохраняет его. Все промежуточные положения ползунков отбрасываются.
Отмена/крестик не записывают pending color или историю.

### Живое обновление стекла из общего session-конвейера

ReflectionDesktopPreview подписан на SettingsSession.Current.DirtyChanged,
которое используется страницами настроек и вызывается после external-sync
существующего RegistrySnapshotWatchService (HKCU/HKLM DWM). Новых registry
watcher/timer-polling нет. После debounce 150ms и проверки PreviewState обновляются
только FlatGlassPreviewLayer, через прежний CompositionWallpaperPipelineBuilder.
Очередь стекла сериализована, устаревшие запросы отсекаются revision/dispose.
Пути обоев переиспользуются из последнего общего wallpaper refresh, без нового
COM-чтения для каждого DWM-сигнала. Intensity отражения перечитывается без
перегенерации его bitmap. Цвет пикера, история и recipe не меняются. Подписка
снимается при Dispose. Внешние записи видны после штатного debounce/settle
общего session watcher, а не синхронно с каждой записью реестра.

Топология мониторов пока фиксирована при создании диалога; обработка hot-plug
в этой правке не добавлена.
