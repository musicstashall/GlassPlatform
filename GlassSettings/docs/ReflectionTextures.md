# Отражения: PNG-плитки, SVG и генерация полотна

Актуальная реализация GlassSettings. Исходники находятся в
`OpenGlass/Resources/GlassReflection`, поставляются пакетом OpenGlass Resources;
пользовательский PNG для OpenGlass формируется отдельно в ProgramData.

## Источники и коллекция

| Pivot | Источник | Применение |
|---|---|---|
| Текстуры | `Textured/*.png` | Маленькая RGBA-ячейка замощения; повторяется до размеров виртуального рабочего стола |
| Рисунок | `Pattern/*.svg` | Самостоятельная векторная композиция, растеризуется в PNG; здесь же «По умолчанию» |
| Другие | Растровые изображения в корне `GlassReflection` | Применяются как есть, без генератора и диалога обработки |

Прежние растровые Pattern поддерживаются прежним путём, но не получают SVG-настройки.
Каталог Tests не включается в коллекцию. Переключение категории не пишет в DWM;
при загрузке страницы выбирается категория активного исходника. «Настроить»
доступно для выбранной текстуры/SVG, не для стандартного отражения и passthrough.
Имена исходников должны быть уникальны между генерируемыми категориями: итоговое
имя — имя исходника с расширением `.png`, без добавленных размеров.

### Пиксельные текстуры

При масштабе 100% пиксели копируются в нативном размере: нет растяжения маленькой
плитки на весь экран, зеркалирования или выдуманного центрального кропа.
Правый/нижний остаток холста заполняется частичным повтором ячейки. Только явный
масштаб пользователя меняет размер ячейки, с округлением и alpha-aware bilinear
пересчётом. Мягкость рассчитывается с периодическим окружением ячейки; шум
добавляется уже после замощения на **весь** холст.

Рабочие пары Dark/Lite имеют одинаковую альфу: Dark RGB #000000, Lite #A0A0A0.
Утверждённые текстуры: FrostWeave, DiagonalWeave, MicroBasket, FineDiagonal,
DragonScale, MicroChevron, CircuitMaze, CrossStitch, TwillWeave. CircuitMaze
имеет согласованное мягкое периодическое сглаживание. Периодические проверки
сами по себе не доказывают визуальную бесшовность в OpenGlass.

Подготовка исходных 01/02 (не путать с масштабом пользователя):
- FrostWeave, ранее GlassReflection_01: ячейка 15×13 от (0, 63), увеличенная
  до 21×18 — X 140%, Y 138,46% с округлением. Различия альфы в повторяющихся
  сегментах оригинала приняты за артефакты пересохранения; рисунок не зеркалится.
- DiagonalWeave, ранее GlassReflection_02: ячейка 5×5 от (1, 0), увеличенная
  до 8×8 (160%, а не 200%). Исключён аномальный первый столбец оригинала.
  Это соответствует переходу 1200×675 → 1920×1080.

`ResolveSource` понимает прежние имена 01/02 для выделения исходника и защиты
его от удаления. Уже записанные DWM-пути автоматически не мигрируются.

### Векторные рисунки

Самостоятельные SVG-пары: SilkWave, FoldedVeil, CornerGlow, PrismGlints,
LiquidCaustics. Это реальные векторы без встроенных растровых изображений;
геометрия и прозрачность в Dark/Lite совпадают. `viewBox` и
`preserveAspectRatio` определяют растеризацию; текущие композиции используют
1920×1080 и `none` для заполнения холста. Пользовательский масштаб применяется
от центра, при уменьшении остаются прозрачные поля. Мягкость ограничивается
краями холста, не заворачивается на противоположный край.

Рендерер — SVG.NET (`Svg` 3.4.7, System.Drawing, Windows). Профиль ограничен:
контуры, простые фигуры, группы, градиенты, clipPath, заливки и прозрачность.
Запрещены DTD, processing instructions, CSS, скрипты, шрифты/текст, image,
use/href, фильтры и внешние ресурсы. XML resolver отключён; до передачи в
SVG.NET проверяются положительные списки элементов/атрибутов. Ограничения:
256 KiB исходника, 512 элементов, глубина 32. SVG вне Pattern не включаются
в коллекции материалов или атласов. SVG напрямую в OpenGlass не передаётся.

## Диалог обработки

Две группы Pivot — **Изображение** и **Шум**, общий размер заголовка 14.
Выбранная группа запоминается только на время жизни процесса, включая отмену
и закрытие крестиком; восстанавливается после Loaded Pivot. Числовые поля
используют `GlassSettingsNumberBoxStyle` и Inline «− / +», как Popup → Анимация.

| Параметр | Диапазон / поведение |
|---|---|
| Масштаб | 25–200%, по умолчанию 100% |
| Непрозрачность | 0–100%, по умолчанию 100%; применяется к рисунку вместе с шумом |
| Мягкость краёв | 0–20 px, по умолчанию 0; alpha-aware фильтрация цветов без тёмных ореолов |
| Тип шума | Без шума / Мягкое / Плёночное / Точечное / Блочное / Мелкозернистое |
| Интенсивность шума | 0–100%, по умолчанию 0; сила слоя |
| Плотность зерна | 0–100%, по умолчанию 50; доля активных зёрен, не увеличение их размера |

**Без шума** отключает интенсивность/плотность в UI и исключает их из рендера,
но сохраняет введённые значения. Параметры изображения продолжают применяться.
**Применять обработку** отключает вообще все эффекты, сохраняя их значения:
текстура нативно замощается, SVG растеризуется без дополнительных эффектов.
**По умолчанию** справа от тумблера восстанавливает значения из таблицы.
**Отмена/крестик** ничего не публикуют; **Применить** передаёт настройки в
существующий serial-конвейер страницы. Нет записи в HKCU из самого диалога.

Живое превью 384×216 использует тот же генератор с debounce и защитой от
устаревшего async-результата. Карточка имеет радиус 8px с клипом содержимого,
усиленный кант, ThemeShadow Z=16. Бело-серо-синяя шахматка #FFFFFF/#99AABB имеет
непрозрачность 7% над фоном темы; она существует только в UI, не в PNG.
Имя над карточкой имеет верхний отступ. Внешний ScrollViewer — страховка для
маленького окна/увеличенного текста, обычные параметры разделены по вкладкам.
Миниатюры самой коллекции имеют ровную подложку #909090, не шахматку;
текстурные миниатюры 148×92 повторяют нативные пиксели. Атласы не изменены.

Шапка спойлера следует [общей политике адаптации](GlassSettings-adaptive-layout.md):
«Настроить» слева от слайдера, трек 120–200 px. После переноса таблицы под
заголовок остаётся единый бюджет ширины. При недостатке места для суммы минимумов
`StackFixedActionBelowSlider` переносит кнопку ниже слайдера на третью строку;
возврат идёт в обратном порядке с гистерезисом 1 px. Пороги измеряются общей
таблицей, страница не содержит собственного resize-конвейера.

### Типы шума

Шум — независимый ахроматический слой по всему холсту, включая прозрачные пиксели.
Он не наследует цвет рисунка. Поле g ∈ [−1, 1] задаёт яркость 127.5×(1+g),
а альфа — |g|×интенсивность/100×0.35×коэффициент типа. Почти нейтральные зёрна
прозрачны, а не образуют равномерную серую заливку. Композиция source-over
в straight BGRA предшествует общей непрозрачности. Рендер детерминирован.

| Сохранённый ID | Тип | Характер |
|---|---|---|
| −1 | Без шума | Пропуск шума независимо от интенсивности и плотности; значение по умолчанию |
| 0 | Мягкое | Плавная интерполяция равномерного поля, характерный шаг 2 px |
| 1 | Плёночное | Смесь масштабов 2/1 px, гауссовы отсчёты Box–Muller, ограничение ±2.5σ |
| 2 | Точечное | Отдельные смещённые круглые зёрна в сетке 3 px; покрытие 2×2 субпикселя |
| 3 | Блочное | Намеренные квадратные фракции 2×2 px |
| 4 | Мелкозернистое | Независимые пиксели шести яркостей, без интерполяции; ранее «Наждачный» |

Типы оставлены раздельными: общая интерполяция мягкого/плёночного не означает
одинаковое распределение или спектр. Плёночный тип — стилизация, не физическая
модель фотоплёнки. Плотность выбирает кандидатов зёрен отдельным hash; процент
покрытия зависит от формы и перекрытий и не обязан равняться параметру.

Сила пяти типов согласуется по sqrt(mean(g^4)) на поле 96×96 при полной
плотности, что учитывает совместное влияние яркости и альфы. Более сильные
типы ослабляются до самого слабого, не усиливаются и не клипуются. Это не
обещание одинакового восприятия на любом фоне или при любой плотности.

Мелкозернистое основано на анализе пользовательского NoiseAsset_256x256_PNG.png:
яркости 0/51/102/153/204/255 с количествами 1311/9094/22034/22214/9351/1532.
Средняя 128.30, σ=52.83, горизонтальная корреляция ≈−0.018. Генерируется новое
поле с этим распределением, а не плитка из загруженного файла. Это не обещание
совпадения с материалом OpenGlass, у которого другой контекст композиции.

## Генерация, публикация и состояние

1. `ReflectionTextureService.PrepareAsync` сериализует генерации SemaphoreSlim.
2. Размер — виртуальный рабочий стол SM_CXVIRTUALSCREEN/SM_CYVIRTUALSCREEN;
   стороны не больше 16384, площадь не больше 33554432 пикселей.
3. Проверяется SHA256 источника до/после рендера. PNG-текстуры ограничены
   1024×1024 до пользовательского масштаба. Рендер формирует straight BGRA PNG.
4. Промежуточный файл находится только в
   `%LOCALAPPDATA%\GlassPlatform\GlassReflection\Staging`; временные файлы и
   staging PNG удаляются в finally. Это не публичный путь для OpenGlass.
5. HKCU-состояние инвалидируется. Итоговый PNG (до 64 MiB, путь короче MAX_PATH)
   публикуется **для PNG и SVG в один каталог**:
   **`%PROGRAMDATA%\OpenGlass\Presets\Textured\`**.
6. Перед копированием очищается только этот каталог, включая его подпапки.
   Запись идёт через временный файл/переименование; после успеха остаётся один PNG.
   Reparse points в пути и содержимом отвергаются. Другие Presets и исходники
   не очищаются. Этот каталог — выделенная область генератора: личные файлы
   хранить в нём нельзя. `Presets\Pattern` распознаётся только для старых путей.
7. После публикации сохраняется готовое состояние, затем DWM-путь изменяется
   в [page operation pipeline](GlassSettings-page-pipeline.md):
   RegistryMutation → Cosmetic → NoticeSync (Animating при необходимости).

Рендер выполняется заново при применении; старого кеширования по `.sha256` нет.
Удаление предыдущего файла перед публикацией означает, что ошибка после очистки
может оставить каталог пустым: атомарность всей замены и rollback не заявляются.
При ошибке состояние не объявляется готовым, показывается локализованная ошибка.

Состояние последнего PNG: **HKCU\Software\StanislavKa\GlassPlatform\GlassSettings\Textured**,
значение **State**, REG_SZ JSON. Поля: Version=1, Ready, Source, Output, Width,
Height, SourceHash, OutputHash, Settings. Settings включает ScalePercent,
OpacityPercent, Softness, NoisePercent, NoiseType, NoiseDensity, Enabled.
Прежний NoiseSize оставлен для чтения совместимых записей, игнорируется рендером
и нормализуется в 1. При вставке «Без шума» старые ID 0..4 не перенумерованы;
индекс ComboBox равен ID+1. Это одна запись последнего результата, не профиль
каждого исходника; JSON-файлы и metadata PNG не используются. При чтении
проверяется SHA256 результата, чтобы не принять чужой PNG за свой рецепт.

## Права доступа и безопасность ProgramData

GlassSettings **не повышает права автоматически и не изменяет ACL**. Сам путь
ProgramData не гарантирует возможность обычной записи в существующий каталог.
Для выполнения генерации учётной записи процесса требуются:

- чтение исходных ресурсов и право записи/удаления в собственный LocalAppData;
- создание/запись State в указанном разделе **собственного HKCU**;
- traverse/read на родительских каталогах ProgramData/OpenGlass/Presets;
- если Textured ещё нет — право создать подкаталог в Presets;
- для существующего Textured — перечисление и чтение, создание/запись файлов
  и подкаталогов, переименование, удаление всех прежних файлов/подкаталогов.
  Практически это **Modify («Изменение») на Textured с наследованием на файлы
  и подпапки**; одной Write («Запись») недостаточно из-за обязательной очистки.
- процессам OpenGlass/DWM, читающим результат, — Read и traverse к финальному PNG.

Полный доступ/смена владельца/DACL для обычного рендера не нужны. Не следует
выдавать запись на весь ProgramData, бинарники OpenGlass, каталог пакетов Setup
или всю коллекцию исходников. ACL, если они требуются для обычных пользователей,
должны быть ограничены выделенной генерируемой папкой и управляться установкой/
администратором. В текущем OpenGlass Resources MSI явной настройки ACL для
`Presets\Textured` нет: **нельзя утверждать, что Modify уже выдан установщиком**.
Унаследованные права конкретной установки следует проверять отдельно. Запуск
из Build этих требований не отменяет. При AccessDenied применяется обычная
ошибка генерации; обхода в LocalAppData и скрытого UAC-запуска нет.

ProgramData общий для пользователей, HKCU индивидуален. Один пользователь может
заменить последний PNG другого; проверка хеша выявляет несоответствие, но не
создаёт изоляцию пользователей. SemaphoreSlim защищает только этот процесс:
межпроцессная/межпользовательская блокировка не реализована. Новый PNG заменяет
предыдущий и для других DWM-партиций. Откат DWM-снимка не возвращает старое полотно.
Автоматическая регенерация при смене конфигурации мониторов пока не подключена.

## Код и проверка

Основные файлы: `DwmThemeDetailPage.xaml(.cs)`, `ReflectionSettingsDialog.cs`,
`ReflectionTextureService.cs`, `ReflectionRenderSettings.cs`,
`ReflectionPixelEffects.cs`, `SvgReflectionRenderer.cs`, `PlatformPaths.cs`.

Переносимые проверки из корня:

```sh
python3 GlassSetup/tests/reflection_textures_contract.py
python3 GlassSetup/tests/svg_reflections_contract.py
python3 GlassSetup/tests/reflection_settings_contract.py
python3 GlassSetup/tests/spoiler_header_controls_contract.py
python3 GlassSetup/tests/openglass_resources_contract.py
```

Чистые пиксельные C# тесты (без WinUI и обращения к реестру):
`dotnet run --project GlassSetup/tests/ReflectionPixels/ReflectionPixels.csproj`.
Контракты и синтаксический разбор не заменяют компиляцию/исполнение.
В среде работы без .NET SDK этот проект и Windows runtime не запускались.
Для выпуска нужны Windows-сборки x64/x86, восстановление SVG.NET, проверка
превью и PNG в OpenGlass, resize шапки, повторное открытие диалога, отмена,
HKCU, AccessDenied/удаление/очистка, ограничения PNG и SVG, несколько мониторов
и поведение при замене результата другим пользователем/процессом.
